# Change Log

## Unreleased

### Fixed

- **A coordinate edit made on a crystal's picture is now written back into the cell the file keeps** — Bond Length, Bond Angle, Dihedral and Rotate Group moved the **displayed** atoms and nothing else, while a crystal saves its base cell and every `rebuildCrystal()` (a bounds change, an undo, a deleted atom) redraws from that cell — so an edit was lost twice: a Save As to CIF or VESTA wrote the old geometry, and the next rebuild dropped it from the screen as well, while POSCAR/cube (which write the displayed atoms) kept it. The displayed picture was never the structure a crystal saves, so the two formats of one session could disagree about it. Every image the builder places now records the **integer cell offset** it sits at relative to its base site (`imgShift`, one line per placement pass), and a new `commitCrystalCoords()` turns the move of any image back into the move of its site: `delta_frac = frac(image) − frac(base) − imgShift`, measured with the same inverse lattice the builder used. The dialogs commit at **OK** — a preview still shows on screen before that and a Cancel still puts everything back — and Rotate Group commits at each committed angle and when the session ends (Done, Clear, a mode switch), so the angle left on screen is the angle in the file. A site drawn many times (a 2×2×2 supercell shows each site eight times) takes the displacement of its **most-moved image**, applied once: a sum would multiply the edit by the number of copies, and any other image would lose most of it. A **bond drawn as a stub across a cell face** is refused by the Bond Length / Bond Angle / Dihedral dialogs with a message — the two atoms on screen are a whole cell apart on purpose, so the distance between them is not the bond length; growing the supercell and picking an image with both ends present is the way to edit it. A bond-order change made in the Bond Length dialog reaches the base bond list too (a bond removed there stays removed), and Cancel puts the cell back from the undo snapshot the dialog opened with — including a bond the dialog had invented. Verified against the **compiled** page with **86 assertions**: the edited length reaches the base cell and comes back out of a CIF written by the shipping Save dialog (1.30 Å read back), a 2×2×2 edit moves the site once rather than eight times, a rotated image keeps the internal geometry through the write-back, the preview leaves the saved cell untouched until OK, one Undo restores the length the cell had, and the create/remove/cancel paths keep the picture and the cell in step.

- **A crystal's undo snapshot is the cell, not the supercell** — `pushUndo()` deep-copied the whole displayed supercell *plus* the base atoms for every crystal edit, so the larger the supercell on screen the more expensive each snapshot was, with up to 50 of them held. A crystal's picture is a pure function of three things — the base cell, its bonds and the bounds — so those three are now the snapshot, and `doUndo()` rebuilds the picture from them. A 2×2×2 view now snapshots exactly the bytes of a 1×1×1 one (measured on CCDC 142619: 124 KB either way, against 519 KB for the 2×2×2 *display* alone) and `pushUndo()` costs the same on both; undo also restores the **supercell bounds** the snapshot was taken under (the six inputs follow), so the picture it rebuilds is the one the edit was made in and the selection's indices stay valid. The molecular path is untouched: a non-crystal structure still snapshots its atoms and bonds. Verified with 15 assertions across both paths: the snapshot carries no displayed atoms, equal bytes at 1×1×1 and 2×2×2, one undo takes an edit out of the cell and redraws the cell view, and a bounds change made before the undo is reverted with the edit.

- **An atom added to a crystal now obeys the cell it is added to** — The Add Atom dialog placed the new site at `anchor + dir × length` and pushed the bond with no periodic shift, so in a small cell the site could land outside [0,1) (the file kept that coordinate while the picture wrapped it), and an anchor near a face could be drawn as one long bond straight across the cell. The new site is now **wrapped into the cell** in fractional coordinates, and the bond records the **integer image** it points at (`shift`, computed from the cell offset between the anchor and the placed position), so the displayed bond is either a normal bond inside one image or a stub into the neighbouring cell — never a long bond through the cell. The free direction for the new atom is read through the **bonded images** as well (each base bond's shift is honoured), so a molecule that straddles a face no longer points a new substituent through the wall. Verified against the compiled page: a site added at 0.98 of the cell wraps to 0.16, its bond carries shift (0,0,1), the bond length through that image is exactly the requested 1.09 Å and no unshifted bond on screen spans the cell; with a bonded anchor the new atom points away from the neighbour's image.

  The three changes are guarded by a new suite (`.workbuddy/tools/verify_crystal_edit.js`, **86 assertions**) with five mutations — the image offset dropped from the whole-molecule pass (16 failures), the write-back taking the least-moved image instead of the most-moved (1), the added site's shift zeroed (5), the display atoms put back into the crystal snapshot (5), the bounds left unrestored on undo (3) — every one caught. The existing suites are unchanged and green: 80 crystal, 140 CIF, 237 ghost, 157 display-style, 105 keyboard, 101 clipboard, 67 provenance, 48 selection, 2 870 aromatic-dash, 192 toolbar, 44 autoplay, 159 ORCA, 80 view-card and 12 pick-style assertions, and the client script re-parses (9 743 lines).

### Added

- **Whole molecules at the cell boundary — the crystal builder now unwraps every component and copies it complete** — A CIF wraps each atom into the cell before the viewer ever sees it, so a molecule straddling a face owns a bond that crosses that face, and the old grouping test — "does any bond of this component cross a face?" — put such a molecule on the periodic shelf: drawn as fragments cut at the boundary, with stub bonds pointing at images that never arrive. On CCDC 142619 that was **every one of its ten molecules**, and none was ever seen whole. The grouping now asks the question that actually separates a molecule from an infinite chain: **are the component's bond cycles consistent?** Each component is walked once with a periodic-image offset per atom (the unwrap), and a cycle that comes back to a shifted image marks the whole component genuinely periodic — that is what diamond and a polymer chain are, and they keep the old per-atom boundary behaviour and their face-cut bonds. Everything else is a **finite molecule**, and it is copied whole: each image whose **unwrapped centroid** falls inside the supercell bounds is placed complete, atoms outside the bounds included, so the boundary cuts nothing and splits no bond. The test is half-open on the upper face, so a centrosymmetric molecule sitting exactly on the boundary is one image, not two; a copy margin constant (`CRYSTAL_COPY_MARGIN`, default 0, convertible per axis to an Angstrom expansion) is there for when a slab should keep the molecules that only just lean out. Each placed atom records **which periodic image of its base site it is** (`cellI/J/K`, exact integers from the unwrap), the field the selection remap and the tooltip build on. The bounds-remap identity is pinned: every atom shown at 0..1 exists at 0..2 under the same `(baseIdx, cell)` key at the same cartesian position, so a selection recorded before a bounds change finds the same atom after it.

- **Supercell bounds gain presets, Reset and Align Origin — and changing the bounds no longer jumps the view or loses the selection** — The panel's six inputs stood alone: no way to ask for the standard 2×2×2, no way back to the unit cell, and every change re-computed the structure centroid, so the whole picture leapt sideways exactly when the user was comparing before and after. **One door now serves every way the bounds change** — the six inputs, the **2×2×2 / 3×3×3 / 4×4×4 presets** (the origin-aligned 0..N supercell, so 2×2×2 is eight cells, not nine), **Reset** (back to 0..1) and **Align Origin** (same spans, low corner moved onto the lattice origin) — and the door does three things in order. It **guards the size** (below). It **keeps the old rotation centre** (`rebuildScene(true)`): the atoms the previous bounds already showed keep their exact screen positions and the new material appears around them, instead of the camera's framing being redrawn around a new centroid. And it **remaps the selection by lattice identity**: each selected atom is recorded as its base site plus image cell, and after the rebuild the same identity is looked up in the new atom list — the selection still points at the same atoms, and only the images the new bounds no longer contain drop out of it. The **cell wireframe draws the subdivision**, not just the outer shell: every integer plane between the bounds becomes a division line (quieter than the box), so a 3×3×3 supercell shows its 27 cells, while 0..1 yields exactly the twelve edges it always drew; the three edges meeting at the low corner are labelled **a, b, c** as sprites in the axes indicator's colours, so the wireframe and the corner gizmo cannot disagree about which direction is which. A bounds change is still a property of the view, not an edit: no undo step, and the save-time provenance reads the bounds as before.

- **A supercell that would be too big is refused before it is built** — The bounds inputs clamp to ±5, so a large structure at the full range could be asked to build `baseAtoms × 1000` spheres — minutes of mesh building for a picture nobody asked for. `applyBoundary` now estimates `baseAtoms × cells` (the same count the per-atom pass would enumerate) and refuses anything past **`MAX_CRYSTAL_ATOMS` = 20 000** — the same ceiling the clipboard refuses fragments over — with a dialog that says what the bounds would build and what the limit is. The refusal changes nothing: the structure, the camera and the six inputs (which keep showing the bounds still in force) are exactly as they were, and the same guard covers the presets, so no button can walk around it.

- **A crystal atom's tooltip and the structure panel now say what it is** — The hover tooltip gave an element, a display index and a Cartesian position — for a crystal that is half the answer. A crystal atom's tooltip now also carries its **fractional coordinates**, **which periodic image it is** (`cell (i,j,k)` — so the different images of one site are finally tellable apart), the file's own **site label** (`C12`, `O1W` — the CIF parser now records, per expanded atom, the `atom_site` label it was expanded from, and the label travels on the atom through deletion and disorder removal), and the **occupancy**. A molecular structure's tooltip is byte-for-byte what it always was — the extra fields simply do not exist there, and the comparison's right half is excluded too. The **structure panel** gains the crystallographic constants of the unit cell itself: the **volume** (the lattice determinant), **Z** — the number of whole molecules the cell contains, which is exactly what the unwrap pass already counted; a cell whose only component is an infinite network has no meaningful Z, and the line stays out rather than showing a number that would be one — and the **density** implied by the cell's occupancy-weighted mass over its volume, from a standard-atomic-weight table the page carries beside the atomic numbers; an element the table does not know leaves the line out rather than guessing a mass. Every line reads only what the page already has, so a panel driven on a stub crystal without a lattice shows none of them and the molecular layout is unchanged.

  Verified against the **compiled** page — `rebuildCrystal`, `detectCrystalBaseBonds` and `computeCrystalInv` cut out of it and driven against real CIF fixtures — **80 assertions**: 142619 at 0..1 showing one atom per base site with no cut bond and its displayed molecules equal to the base molecules size for size (no fusing, no splitting); image accounting at 0..2 (8 whole images per molecule, 8× the base bonds); a synthetic molecule wrapped across a face copied whole into one image (and a slab holding none of its centre drawing no fragment of one); diamond and a polymer chain staying per-atom per cell with their split bonds and no Z; the bounds-remap identity at 0..1 → 0..2; the wireframe's twelve edges at 0..1 and fifteen division lines at 2×2×2; the panel lines (volume, Z, density — and none of them invented for a lattice-less stub or an unknown element); the site label travelling from the CIF through the payload; and the refusal path restoring the six inputs. The existing suites are unchanged and green: 140 CIF (with 20/20 mutations caught), 157 display-style, 237 ghost, 2 870 aromatic-dash, 101 clipboard, 67 provenance, 192 toolbar, 48 selection, 105 keyboard, 44 autoplay, 159 ORCA, 80 view-card and 12 pick-style assertions, and the CIF baseline snapshot's atom arrays are byte-identical.

### Added

- **A display style for the view — ball and stick, space-filling or stick — that does not fall back when the toolbar moves on** — The View card gains a **Display** selector with three models: **Ball & Stick** (the drawing this viewer has always produced, and the default), **Space-filling** (each atom as its van der Waals sphere, no sticks) and **Stick** (the sticks stay and every sphere shrinks to the thickness of the sticks that meet at it, so the model reads as tubes with no beads and no notch at a bend). The choice is a property of the **view**, not of a mode: it is one variable above every block that reads it, and no mode switch, frame, molecule, undo or edit resets it — leave View for Bond Length, Move Atoms or MM, or switch a trajectory's frame, and the structure is still drawn the way it was chosen. The View card is only where the style is *changed*; the control leaves with View, the style does not.

  **One rule, three readers, so the picture cannot be half one style and half another.** The atom radius (`drawnRadius`) is the single answer to "how big is this atom": ball returns `atomRadius` unchanged — the default drawing is literally the old expression, not a copy of it — a space-filling sphere is the element's van der Waals radius (the table the host resolves a script's `Surf` probe against, pinned element for element), and a stick joint is the thickness of the thickest stick meeting at that atom, read off the bond list in one pass, so a script that draws thin lines does not grow beads and an isolated ion does not vanish (it keeps the default joint). A ghost stays the small marker it is in all three styles: it is a point without a nucleus, so neither a van der Waals sphere nor a joint is a meaningful size for it. **A space-filling model draws no sticks** — the decision lives in `createBond`, the one door every piece is declared through, so the scene build, a moved region's rebuild and both halves of a comparison obey it without being told again; **a stick model changes only the spheres**, and every piece keeps the transform it already had. A VMD script's per-atom sphere scale is applied in the ball style (that is what it is for) and deliberately not in the others: it is a ratio inside a ball-and-stick recipe, and a zero there means "this representation draws no sphere", which in a space-filling model would empty the picture; the script's colours and surfaces still apply. A comparison is restyled whole: Diff draws its right half from its own model, so a style change rebuilds that half too rather than leaving one structure in one model and the other in another — in place, so the two view states, the camera and the pan stay where the user put them, and carrying the difference marks and the right-hand selection across the rebuild instead of dropping them.

  **A joint is not something a hand can aim at, so the stick model gets a pick target of its own.** Picking is how every measurement, selection and edit starts, and a stick joint is deliberately thin: on a 24 Å structure a 0.24 Å joint is under two pixels across, and **only 4 of its 12 atoms could be pointed at at all** (measured in a real engine, sweeping the pointer over the structure). A press or a hover that misses every sphere is therefore re-tested — **in the stick style only** — against a cone around each atom whose radius is fixed in **pixels**, so the pointer needs the same precision at every zoom level and the nearest atom along the ray wins. The default balls and the space-filling spheres are their own targets and are **untouched**: the same page with the rule disabled reaches exactly the same atoms at exactly the same points, count for count. The hover tooltip also stops carrying its own copy of "which atom is under the cursor" — it asks the same `getClickedAtom` a press does, so the two can never disagree and the wider target applies to both. A change of style re-takes the panel layout as well, because the panels keep clear of the box the *drawn* spheres occupy and a space-filling model is several times the footprint of the balls it replaced.

- **Ghost atoms — a position with no nucleus, and every format that can say so** — An atom can now be a **ghost**, which is what a counterpoise (BSSE) calculation and a geometry definition both need: a point that keeps the element it stands for but has no nucleus, no electrons and no bonds. **Add Atom** gains a *Ghost atom* switch and an `X (dummy point)` element, and **Replace Atom** gains a *Ghost* switch that converts the whole selection into ghosts **of their own elements** in one step — the gesture a counterpoise setup actually needs (select one monomer, make it ghosts, save the Gaussian input), and the only reading under which a mixed selection means anything; the switch is pre-ticked when everything selected is already a ghost, so pressing Replace is never a silent un-ghosting. A ghost keeps its element (`C-Bq` in a Gaussian input, `C:` in an ORCA one) or is a bare dummy (`X`), is drawn as a small faint grey-blue marker whatever it stands for, and is labelled `C*3` / `X5` everywhere the page names an atom — the tooltip says `(ghost)`.

  **A ghost is excluded from everything that needs a nucleus, at one predicate.** `isGhostAtom` (the `ghost` flag *or* the dummy element `X`, both spellings meaning the same thing) decides drawing, colour, formula, electron count, label and every bond guard, so a structure cannot have a ghost that one pass treats as an atom and another does not. **Bond perception never bonds it**: the connectivity pass leaves a ghost out of the spatial grid and normalises it to a dummy for the valence passes, so a ghost laid exactly on top of a real carbon adds no sticks, does not perturb one real bond (the derived bond list is compared against the ghost-free structure's, bond for bond), and does not send the valence solver after a component it could never fix. **A bond that touches a ghost is dropped on load** — a PDB `CONECT`, a MOL2 bond block or a Gaussian `connect` section may name one, and `ensureBonds` is the single door every load path passes through. The **formula and the electron count** leave ghosts out and the info panel lists them separately (`Atoms: 4 (2 ghosts)`, `Ghosts: 2 (no bonds, no basis, not in the formula)`); **Add H** and **Molecular Mechanics** skip them, a ghost is never in the mobile set, and its Lennard-Jones well depth is zero — so a ghost parked 1 Å from a carbon cannot drag it (without that, the same run throws the carbon 2.4 Å); the **Bond Length** dialog refuses to create a bond to one and puts its order control back to None. Turning a ghost back into a real atom re-derives **that atom's** bonds from the geometry — the same detector a load uses, and only bonds that do not exist yet are added, so nothing else is rewritten — in the same undo step. Ghost atoms are refused for **crystal structures** with a message: CIF, POSCAR, VESTA and cube have no way to say "this site has no nucleus", so a ghost written to one would come back as a real atom.

  **Every format writes its own spelling, and reads all of them back.** Gaussian `C-Bq` / `Bq`, ORCA `C:` / `X`, XYZ `X`, PDB `X` with a `HETATM` record and a `DUM` residue, MOL2 `Du`, MDL Mol `*`, TURBOMOLE `$coord` `q`, MOPAC `XX`; the parsers recognise all of these plus `Xx`, `DA`, `Dummy` and `(Bq)`. The formats with no ghost concept are given the **dummy** spelling rather than the atom's, because a ghost must never come back as a real atom, and the Save dialog says which is which before the file is written. A structure **without** ghosts saves byte-identically to before (pinned, format by format), and the provenance line records the change in words (`1 ghost atom added`, `2 atoms made ghosts`, `1 ghost made real`) so the file says what was done to it.

- **Esc, Ctrl+Z and Ctrl+S — the three keys a hand reaches for before the mouse** — The page's keyboard now has one door: these three are settled at the top of it, before the viewer's own keys (arrows, Delete) are read, so a shortcut and an existing control can never both answer the same press. The modifier is **Ctrl on Windows/Linux and Cmd on macOS**, and each shortcut answers to the **key** *or* the **physical code**, so it still fires on a layout that reports a different character — an AZERTY Ctrl+Z arrives as `z`, a Cyrillic one as `я`, and both are the one press the user made. **Esc backs out of exactly one level**, in the order the states were built up: it presses the open dialog's own **Cancel** (the path that knows what cancelling means — several of them put back the geometry they were previewing — with a plain hide only as the fallback for a dialog that has no cancel button), else **abandons a box-select rectangle** still being dragged (it has selected nothing yet), else **leaves the current tool for View**, else **lets go of the selection**. Every step takes back something the user started and nothing else, so a second press can only undo a smaller thing and can never touch the structure; and Esc is the one key that also works from inside a dialog's text field, because that is how a user gets out of it. **Ctrl+Z is the Undo button**, and it refuses two states where an undo would do damage rather than work: while a **dialog is open** (it previews geometry on top of an undo step of its own — an undo behind its back would split the two apart, and its Cancel would then pop someone else's step) and inside a **text field**, where Ctrl+Z stays the browser's own text undo. **Ctrl+S opens the same Save dialog as the Save As button**, and with that dialog already up it **presses its Save button**, keeping the format already chosen — so "Ctrl+S, pick a format, Ctrl+S" saves without the mouse. The three also decline what is not theirs: no Shift (Ctrl+Shift+Z is redo elsewhere and there is no redo here), no Alt (AltGr sends Ctrl+Alt), no stacking a dialog on a dialog. Nothing is contributed to the editor's keybindings, so no VS Code or Trae shortcut is taken over, and the keys that were already there keep their meanings untouched — arrows still rotate and spin, Delete still deletes, Ctrl+arrow is still fragment rotation, and typing in a field is still the field's. The Undo and Save As buttons now say their own keys in their tooltips (`Ctrl+Z` / `Cmd+Z`). Verified by cutting the keyboard block out of the **compiled** client and driving it in a stub DOM with **63 assertions**, one per real key event and its focus: Esc's four levels and its no-op case (which must leave the default to the host), a dialog cancelled from inside its own field, Ctrl+Z refused behind a dialog and inside a field, Cmd on macOS, the AZERTY and Cyrillic presses both reaching the same action, Ctrl+S opening the dialog and confirming it, Ctrl+S opening nothing on top of another dialog and not firing from a field, Ctrl+Shift+Z, Ctrl+Alt+Z and Ctrl+Shift+S all left alone, and the pre-existing arrow / arrow-in-a-field / Delete / Ctrl+arrow behaviour unchanged — plus the integration side a stub cannot see: every name the handler calls is one the client really declares, the listener is registered **exactly once** on the document (a second door would make each shortcut answer twice), and the block sits inside the page's own IIFE. Five mutations — Esc handled after the field guard, Ctrl+Z let through behind a dialog, Ctrl+S no longer confirming, Esc skipping the tool level, Ctrl+S no longer checking the field — each fail exactly the matching assertions (10, 1, 2, 1 and 1), so none of them is vacuous; the whole page's client script is re-parsed after the edit to catch a template-level syntax slip.

- **Ctrl+C / Ctrl+X / Ctrl+V — a clipboard for the structure itself** — A **fragment** can now be copied out of the view and pasted back into it, which is what "duplicate this ligand" or "put that group over there" actually needs. **Copy** takes the selected atoms and **only the bonds among them** — re-indexed into the fragment, bond orders included — and stores the fragment **relative to its own centroid**, so the payload holds no position at all: a paste is then a translation, and the same fragment can be pasted again and again. **Cut** is copy plus **the same batch deletion the toolbar performs** (so a crystal loses its base atoms and base bonds exactly as a plain Delete does), with **one** undo step for the pair, and the status line says how to get the fragment back. **Paste** appends the fragment **beside** the structure, at the **very spot an import would choose**: the bounding-sphere rule was lifted out of `importStructure` into `placeBlockBeside`, which both paths now call, so the two placements cannot drift apart and the import's own numbers are unchanged (closest atoms 7 Å apart). A paste **selects what arrived**, so it can be moved, cut or copied straight away, zooms out when the copy lands outside the view, and is **one** undo step. **No bond is invented between the copy and its new neighbour**: a paste is not a merge, so unlike Import it does not re-detect the combined system, and the fragment keeps exactly the orders it was copied with. Every refusal is explicit and leaves the structure untouched — **paste on a crystal** (a cell's contents are regenerated from its base atoms, so the copy would vanish on the next rebuild), **cut and paste in Diff mode**, **cut and paste behind a dialog** (which is previewing geometry on top of an undo step of its own), a paste that would pass **20 000 atoms**, and an empty clipboard. Copy is read-only, so it works everywhere, dialogs and comparisons included. The clipboard is the **viewer's own**, not the system one: nothing you copied in another application is replaced, and nothing is ever read back from it. A copy is mirrored into the panel's **localStorage** on a best-effort basis, so a fragment can be pasted into another panel; whatever comes back is re-validated first (a real element symbol, finite coordinates, bond indices in range, size under the limit) and **discarded whole** rather than half-used if it is not a fragment — and with storage denied, copy and paste still work inside the panel. On the keyboard side the three keys obey the rules the other shortcuts set: they are ignored inside a text field (that Ctrl+C/Ctrl+V belongs to the field) and **ignored on key auto-repeat** (a held Ctrl+V would otherwise paste the fragment over and over), cut and paste wait for a closed dialog; copy is unconditional, because the page carries no selectable text of its own (see Fixed). Like the rest, they answer to `e.key` or `e.code` and to Ctrl or Cmd. - **An aromatic bond's dashed line now sits on the same side as its neighbours', so a ring reads as aromatic all the way round** — An aromatic bond is drawn as one solid line plus a six-dash line offset to one side, and that side used to fall out of the bond alone: the offset was the bond direction crossed with the world up axis, which for two aromatic bonds meeting at an atom points two different ways. Seen from the face of a ring, part of its bonds therefore carried the dashes inside and part outside — the ring never looked wholly aromatic, and a chain showed a band that zig-zagged from one side to the other. **The side is now a property of the structure, planned once per bond list.** Each connected aromatic system gets one plane (the cross products of the bond pairs meeting at its atoms, aligned on the least collinear pair and averaged, so one distorted bond cannot tilt a plane it is drawn in), and a walk over the system assigns every bond a side: at a **two-bond atom** the band passes straight through, which is what makes a ring or a chain show one continuous band; a **three-bond atom** is a branch, where each arm takes the side that points most nearly the way the arriving dash points, so a fused ring keeps the arm that stays in its own ring; and crossing a bond **no ring runs through** (a biaryl link) starts a new band, mirrored, because the arms on the far side are a ring of their own and must not inherit the side the band arrived on. A **bounded local repair** settles the atoms a fused system can still leave contradicted — a shared bond belongs to two rings and the walk only knows the one it came through — flipping only bonds whose flip leaves fewer contradicted atoms behind, so a ring that is already consistent is never touched. Finally the whole system is flipped if the majority of its bonds would point away from its own centre, which is what puts a ring's dashes **inside**, the way it is drawn on paper. The dash is now offset **in that plane** (crossed with the system normal) instead of against the world up axis, so it stays perpendicular to the bond and inside the plane however the structure is oriented. Nothing reads the atom order a file happens to use — a bond stored the other way round has its direction, and so its "left", flipped, and σ (which endpoint is atom1) accounts for it — and a crystal's wrapped bond is planned along the line it is actually drawn on, periodic shift included.

  **Nothing else about the drawing moved.** A double or triple bond's second and third lines keep the world-up offset they have always used, and every piece of a single, double or triple bond is placed by exactly the same arithmetic as before — pinned piece for piece against the old formula, with not a hair of difference. A dash piece keeps **no side and no plane of its own**: it reads both from the current plan at the moment it is placed, so a plan that is refreshed reaches every piece that is drawn afterwards without touching one of them, and a piece built before the refresh can never disagree with one built after it. The plan is therefore computed where the bond list is (re)built — a load, a frame or molecule switch, an edit, an Undo, an Import, an MM commit and a Move Atoms release — and again on the paths that turn or bend a geometry in place: a **fragment rotation drag** and an **Alt-drag rotation bake** re-plan as they turn (a ring's plane turns with it, so the dashes would otherwise tilt out of the ring for the length of the drag), a **manual normal-mode displacement** re-plans on every slider move, and a **Molecular Mechanics chunk** re-plans once per chunk. A pure translation changes no direction and does not re-plan, and the **normal-mode playback** deliberately keeps the equilibrium plan: it borrows the geometry for one cycle and puts it back, and a plan that changed sixty times a second could flip a side mid-animation. A per-object material is the expensive half: three.js re-uploads a material's whole uniform set before any draw call whose material id has changed, so ~16 000 distinct materials meant on the order of a million uniform writes in a single frame — enough driver work in one frame to reset the GPU process on Windows, and that process is shared by every webview in the window. Once it is gone no page can create a context, which is exactly why the failure followed every later file and could only be cleared by reloading the window; three.js's message names the symptom and not the cause, and the page had no handler for a context lost mid-session, so the first structure simply went blank.

  Three changes remove it. **Bond cylinders are no longer meshes.** A bond piece is now a plain record — which bond, which half, its radius and colour, the aromatic dash window, the multiple-bond offset — and one shared unit cylinder draws all of them through a single `InstancedMesh`: the piece's radius and length live in the instance matrix and its colour in the instance colour buffer, so the bonds of a structure of any size cost **one draw call and one geometry** instead of one object, one geometry and one material per cylinder. **Atom geometry and materials are pooled**: a sphere is shared by every atom of the same radius and a material by every atom with the same colour, occupancy and highlight state — the highlight (selected, diff-highlighted, plain) is now *chosen* from that pool instead of being written into a per-atom material, which is what made one material per atom necessary before. **Placement is one routine.** A piece's position, orientation and length are read off the two atoms it spans by the same function that a scene build, a Move Atoms drag, a streamed MM chunk and a normal-mode playback all call, so building a piece and animating it can no longer drift apart (the old code kept two copies of that arithmetic — one in the builder, one in the playback — which is also why an aromatic bond's dashes stretched correctly but a multiple-bond line's offset plane could disagree with itself). Measured on the 2175-atom structure: **16 081 objects → 2 177, 16 081 geometries → 6, 16 081 materials → 7** (and ~64 000 GL buffers → ~26), with all 13 906 bond pieces re-placed in **13.6–15.5 ms** and the whole scene rebuilt in **34–40 ms** (min–median of five runs in a Node sandbox, where property access is slower than in the page). The comparison (Diff) scene goes through the same machinery, with two pools so a highlighted bond keeps the orange glow its material carries, and its two sides no longer build a mesh and a material per atom and per bond either.

  The failure path itself is hardened too. A context lost mid-session is caught (`preventDefault`, a message on screen, and a scene rebuild when — and if — it comes back) instead of leaving a blank canvas; the context is released when the page is really going away rather than held until the panel is disposed; and a renderer that cannot be created at all now names what actually fixes it — *"the GPU process of the editor window is unavailable. Run "Developer: Reload Window" (or restart the editor)"* — instead of only repeating three.js. The material pool is a cache that outlives the meshes drawing with it (so an edit or a colour toggle does not re-create every material) and is dropped once it passes a bound no real structure reaches; the atom half of it is the only part that can grow with the data, because **scalar colouring gives every distinct scalar its own colour** — measured at 524 entries for a 2175-atom structure carrying a per-atom scalar, still an order of magnitude below one material per drawn object, and the bonds stay a single instanced mesh either way. One visible detail changed: a dashed aromatic piece is now cut from the shared 8-segment cylinder rather than owning a 6-segment one, on a cylinder 0.08 Å in radius, where the difference is below a pixel.

  Verified two ways, and the second way is the one that matters. The client is booted in a stub DOM and driven directly, and it is *also* booted from the page the **real extension host** builds (`openCustomDocument` + `getHtmlForWebview` run against a stubbed `vscode` module, so no payload field can be missing the way a hand-written one can — VMD payloads, crystal expansion, 647-frame logs, optimisation steps and atom groups all arrive the way they do in the editor). For a 15-file corpus plus the three VMD script samples, a crystal CIF and a `.tcl` that sets a 0.5 sphere scale, the number of drawn cylinders is identical to the pre-change builder's and **every cylinder's position, direction, length, radius and colour matches** to within one float32 ulp (worst delta 9.5e-7 Å, which is the instance buffer's own precision); a control reference that draws every cylinder 2e-3 Å longer is detected in every file, so the comparison is not vacuous. The **draw pass itself is simulated** — one call per mesh, `object.count` instances per instanced mesh, invisible objects and materials skipped — because asserting on the instance buffers is exactly how "the buffer is full but the mesh draws nothing" passes a green run. The features that move bonds were driven through that same client: a drag re-places exactly the pieces of the bonds touching the moved atoms and nothing else, and the release path — re-derivation included — equals a full re-derivation piece for piece; a whole-structure playback equals a full rebuild; a rotation-centre change carries every piece with the geometry; a supercell grown and shrunk back re-places and re-draws everything; selection and diff highlights come from the shared pool and clear back to the shared plain material, on a partial-occupancy atom too; leaving a comparison restores the single structure's drawing. Edge cases: a bond the script refuses to draw, two atoms dragged onto each other (no NaN in any instance matrix), an empty structure, scalar colouring on and off, a crystal's 84 periodic-image bonds (1422 pieces placed outside the asymmetric unit), a lost context (reported, then rebuilt on restore), a page-hide release, and a renderer that cannot be created at all (the message names the fix). **351 assertions, 0 failures** — and the harness found three defects on the way, *after* an earlier 208-assertion run had already gone green: the pool's early-out did not re-attach its mesh to the group a rebuild had just cleared (every bond would have vanished on the first edit), the refilled mesh left `count` at 0 so it drew **no** instances (the bonds were invisible), and entering a comparison stopped applying the left-hand highlight because the flags it sets are only materialised by a later recompute. Each was fixed and the assertions that catch it were kept.

- **A paused Molecular Mechanics run can be continued again, and pausing can no longer leave the panel stuck** — Pausing used to hand the panel a `pausing` state that only the extension host's reply could end, and the reply path ran the whole region re-perception *before* the panel was re-rendered. Anything that stopped the reply arriving — a message dropped, the host busy, the run replaced in the same instant — left the button reading **"Pausing…"** for good, with the run neither stopped in the UI nor continuable; and a failure inside the region re-perception aborted the same handler, so even a reply that did arrive could not put the button back. Three changes remove both halves of that. The panel now has **one toggle button**, the pattern the vibration panel uses: it reads **Pause** while the run goes and becomes **Resume** the moment it is clicked, and the host's answer only *confirms* the state instead of being required to reach it — so a lost, late or duplicated reply can no longer strand the panel (and clicking Resume on a run the host never actually paused is harmless: the host is still pumping, or it resumes the session it kept). **Restore initial** sits next to it as the way back to the pre-run geometry, and therefore back to Start. The host side is **idempotent and always answers** — a pause that arrives twice, a resume of a run that was already going, and a pause for a run that has already finished are all no-ops apart from the reply — and the pump now yields through **`setTimeout(…, 0)`** rather than a chained `setImmediate`, so the message loop is guaranteed a turn between two chunks however the host's I/O is serviced. Client-side, the heavyweight region re-perception is **guarded and moved behind the re-render**: the paused panel (with its Resume button) is on screen first, and a failure there reports "the moved region could not be re-perceived" instead of taking the handler down with it. A chunk already in flight at the moment of the pause is dropped rather than applied, so the geometry the user paused on is the geometry they keep looking at; the host's own pause reply is what settles it (its coordinates are applied even while paused). Verified by driving the real client section against a stub DOM and the real compiled extension code on a real event loop (**38 assertions**): the label flips to Resume on the click itself and back again **with no reply from the host at all**; a chunk arriving while paused moves nothing; the reply's geometry and its unseen history points are applied exactly once; a resume makes progress flow again; a **simulated failure inside `refreshMovedBondsAndMeshes` still leaves Resume on screen** (it used to leave "Pausing…"); the panel returns to Start after the result and after Restore; and on the host, a Pause sent while the run is pumping is answered within milliseconds and no chunk follows it, a duplicate Pause is answered too, a Resume restarts the pump, a Cancel or a disposing panel stops it for good, and the whole streamed run is still byte-identical to the module's single call.

- **Exactly one thing writes the geometry at a time** — Four parts of the viewer write the coordinates, and three of them keep writing *after* the call that started them has returned: a **normal-mode playback** rewrites every atom on each animation frame, a **frame auto-play** replaces the structure on every tick, and a **Molecular Mechanics run** streams coordinates from the extension host (a **Move Atoms** drag is the fourth, a live session on the selection). Any two at once fight over the same array, and the loser is silent: the stop that runs later writes back the geometry *it* started from, so a normal-mode stop could overwrite a run's steps, a frame's coordinates or freshly appended hydrogens, and a frame change could put the previous frame's coordinates back over the frame just loaded. Four holes are closed, each of them at the moment the second writer starts.

  A **frame change** and a **molecule switch** now end a playback before the structure is swapped. A frame change used to end one only through a wrapper assigned over `switchFrame` after the fact — invisible to any caller that reached the function another way, and impossible to find from the function itself — so the guard is now where the replacing happens and the wrapper is gone. A **normal-mode playback** ends a frame auto-play and a Move Atoms session first: an auto-play would otherwise replace the structure on its first tick half a second later, which (through its own frame change) stopped the playback almost as soon as it began. A **landing Add H answer** ends a playback and a Move Atoms session before it appends — the request goes out in one mode and the answer arrives whenever the host gets to it, by which time the user may have started a playback in another one, and the playback's own stop would write the pre-add geometry back over the new hydrogens. And the **auto-play button** ends a playback, a move session and a run when it starts, rather than leaving them to be cancelled by its first tick. With those in place the rule is uniform: every entry that replaces the structure — `switchFrame`, `switchMolecule`, `applyHydrogenResult`, `doUndo`, `importStructure`, `startAddHydrogens`, `startMmOptimization` — ends a playback first, every modal edit goes through the one door (`showModal`) that does, and no wrapper reassigns a function behind its definition.

  Verified by driving the real client. A playback stepped to a quarter period (full displacement) is ended by a frame change, and stepping it again afterwards writes nothing at all; with the guard removed the same sequence fails both assertions, so they are not vacuous. Starting a playback ends an auto-play and leaves the playback itself running. An Add H answer that lands mid-playback ends the playback before the hydrogen is appended, and nothing rewrites the grown structure afterwards. Source-level assertions pin the per-function guards, the shared modal door and the absence of the wrapper: **169 assertions across 29 scenarios**.

- **The page's bond re-detection is complete again, and a structure whose file authored its bonds is now treated as such** — Two wires between the extension host and the page were missing, and between them they disabled every client-side re-derivation.

  **The page's copy of the perception module was missing a function.** `bpSpecDev`, the length-deviation used by the value-relaxation pass, was never added to the serialised function list, so the page's `perceiveBonds` threw `ReferenceError: bpSpecDev is not defined` on *every* call. The host was unaffected — it calls the compiled module — so a structure loaded, drew and rotated perfectly, while everything that re-derives bonds **inside the page** failed: **Move Atoms** on release, **MM Optimize**'s commit and its **Restore initial** (the live per-chunk bond meshes still followed the atoms, but the moved region was never re-perceived, and the panel reported it), the bond-merging step of **Import**, and the skeleton mapping **Diff** builds its comparison from — all four call the same entry point. The Move Atoms release handler threw out of the mouse-up, so the rest of the release was skipped with it. The serialised list now names all 35 helpers, and the page's detector is compared with the host's module **bond for bond over 8 structures (2592 bonds)** — identical on every one.

  **The flag that says "this file stated its own bonds" never reached the page.** `hasExplicitBonds` — true for a MOL2 bond block, PDB `CONECT` records, a GJF `connect` section, a SMILES import — was left out of the page's payload, so `MD.hasExplicitBonds` was always undefined and the client treated every structure as auto-detected however it had been loaded. Two things followed. On a structure with authored bonds, **Move Atoms** re-derived the moved connected component from geometry instead of keeping what the file said, so the documented behaviour ("keep their authored bonds and orders; only a bond whose endpoints are pulled beyond the bonding cutoff is dropped, deletion only") was unreachable code — and **MM Optimize** reaches the same pass at every commit. And **Import**'s merge reads the same flag: importing an auto-detected file beside a structure that had authored bonds took the "re-detect everything" branch, discarding the authored orders of the structure that was already on screen. The payload carries the flag now, and both branches behave as documented — measured: an order the file gave a bond survives a move (while a bond pulled past the bonding cutoff is the only thing dropped), the same move on an auto-detected structure does re-derive the component, and a MOL2 with `BOND` records reports authored bonds.

  Two smaller findings from the same sweep. A progress chunk that moves nothing no longer takes an **Undo** step: the snapshot is now taken in front of the first coordinate that actually changes, so a run whose first report is the input geometry unchanged leaves the Undo stack exactly as it found it (and counts no moved atom). And a re-derivation keeps a bond's **drawing properties** — a VMD script's per-bond radius above all — instead of replacing the bond with one that carries only its endpoints and its order, so re-deriving an order can no longer silently restyle a bond the script asked to be drawn at its own thickness (or draw one it said not to draw).

  Verified with the real client script booted in a stub sandbox and driven through the situations the behaviour is defined by — **139 assertions across 28 scenarios**. Two of the checks are new and general: every `MD.<field>` the client reads must have a source (a key in the host's payload, or a write of its own), and every `bp*` helper declared in the perception module must appear in the serialised source — the second is the one that catches exactly the missing-`toString()` mistake above, and the first surfaced the missing payload key. Alongside them the harness now puts the structure through the same `ensureBonds` the host does before it boots the page; a raw parse of a GJF without a connect section has no bonds at all, and that gap in the harness is what had kept the first failure invisible.

 — Once a run was no longer the only thing happening, three things could go wrong, and each is now closed.

  **A progress chunk in flight at the moment Pause was clicked was dropped whole, and with it its history points.** The coordinates did need to be held — that is what a pause is for — but the points did not: the host advances its "already sent" mark the instant it posts a point, so a point dropped on this side is never sent again, and the energy and force curves lost every step in that window for good (the slower the host was to notice the pause, the bigger the hole; the curves ended up shorter than the run they describe). The two halves are now separated: a chunk that arrives while the view is held is **recorded** — its points join the curves and its step, energy and forces update the readout — while its coordinates are **not** drawn onto the structure, and the host's own pause reply then carries the geometry it actually stopped at. So the curve is complete *and* the geometry the user paused on is the geometry they keep looking at. A chunk for a run that has already stopped on this side (its result applied, its geometry restored) is still ignored outright, and it is now refused up front rather than after the bookkeeping.

  **The host's pump was scheduled without naming the run it belonged to.** A chunk chain left over from a run that had been cancelled and replaced woke up and pumped whatever run was current — so the new run was driven by two chains at once, at twice the chunk rate it had asked for, and every cancel-and-restart added one more. The pump is now handed the run it was scheduled for and stops as soon as it no longer owns the panel's run; no bare schedule call is left.

  **A `mmPause` / `mmResume` for a run the host no longer had was answered with nothing.** The panel flips its toggle the moment it is clicked (that is what keeps a lost reply from stranding it), so it was waiting for a confirmation that could not come: a Pause button that did nothing, and on the resume side a run that looked live while nothing was running. Both now answer — with the ending of that run id — so the panel returns to Start. The reply addresses the run the panel asked about, so a run that *is* in flight is untouched by it.

  Also fixed, in the same pass: the two curves were drawn into the panel's **padding box** instead of the canvas's own box, so they came out ~20 px wider than the element showing them and their right edge — the end-of-axis step label with it — was clipped; and nothing redrew them when the layout reflowed, so a window resize, a panel move or a close-then-reopen left them at the width of the previous layout. They are now sized from the canvas's own box with the display box left to CSS, and `layoutPanels` redraws them, so a reflow re-fits them (a no-op unless the Molecular Mechanics panel is up with a run behind it). Finally, starting a run is refused while an **Add H** request is still in flight, and an Add H answer that lands later ends the run — appending atoms is the one structure change that does not pass through a mode switch, and therefore the one that could hand the optimiser a structure it did not start from.

A pause with a chunk in flight: the curve keeps every point (2 → 4 → 6 rather than 2 → 3 → 4) while the geometry stays exactly where it was until the host's snapshot lands, and the resume continues from that snapshot. A finish that arrives while the panel is holding a pause ends at "done" instead of stranding Resume. Alongside: a cancel from another mode (the panel hides and a late chunk is ignored), a stale run id, a selection change and a parameter and a preset change mid-run (the run, its history and its buttons all survive the panel rebuild), the panel closed with the reopen label tracking the step, Restore initial, a second start while one is running (refused), and the two Add H interactions. The three host-side properties are asserted against the source — the pump binding, both always-answer branches, the absence of a bare schedule call — and the host engine is re-run end to end to confirm this pass left it alone: `optimizeSelection` still returns a monotone result, names only the selected atoms and never mutates its input.

- **Molecular Mechanics now coexists with every other way the viewer moves or replaces the structure** — The panel was already compatible with the features it is *reached* through (a mode switch, an Undo, an Import, a frame, a molecule, a comparison, Add H each end the run). What it was not compatible with were the viewer's own **playbacks**, which write the very coordinates a run writes and did not know about it. A **normal mode** rewrites every atom's position on every animation frame and puts the geometry it started from back when it stops — so playing one under a live run fought it frame by frame, and stopping the mode then silently rewound the run's progress. Starting a mode now **ends the run first**: the geometry the run had reached stays on screen, exactly as any other cancel leaves it, the status bar says why, and the mode plays over that. It is the mirror of a run stopping a playback when it starts (which it already did), so the two can no longer both own the structure. A **frame auto-play** replaces the structure on every tick, which ends a run as surely as clicking Next does, so starting a run now stops the auto-play first — and the stop is a named step (`stopFrameAutoPlay`) rather than an inline block only the button could reach. Both are done **before the run captures "where it began"**, so the geometry Restore writes back is the one on screen at the click and not a half-drawn vibration amplitude. Two smaller things in the same pass. The panel now **names both atom sets while a run is live** — the run's own atoms, which its buttons act on, and the view's selection, which is the next run's — because clicking atoms mid-run used to relabel the panel as if the running optimisation had followed them (changing the selection mid-run stays allowed; it is simply no longer ambiguous what the buttons will do). And a chunk is now a **fixed amount of work rather than a fixed number of passes**: measured here, ten passes cost ~3 ms on a 72-atom structure but ~42 ms (worst chunk 66 ms) at 356 atoms, so a fixed ten would hold the message loop for a large part of a second at the 3000-atom cap and a Pause would land that much late; the count starts at ten and is adapted from what the last chunk actually cost. The answer cannot depend on the slicing — a run stepped in chunks of 1, 2, 3, 7 or 1000 passes reproduces the single-chunk result **byte for byte**, coordinates included, re-verified. Finally, a curve that holds only its starting point (a run that has taken no step yet) is **marked with a dot** instead of reading as "no data" for the whole first chunk.

  Verified on the real client script booted in a stub sandbox — **115 assertions**: the earlier 84, plus a live run ended by a normal-mode playback (the geometry it reached kept, no rewind, the reason on the status bar), a run started while an auto-play was running (auto-play stopped, its button reset, the run live), both atom sets named and stable across a mid-run selection change, the adaptive-chunk properties, and the single-point marker. The host optimiser was re-checked with the real module as well: `undefined` input, NaN coordinates, coincident atoms, an out-of-range and fractional selection, an empty selection, zero atoms, and an unknown preset with wrong-typed values all return a structured answer in bounded time; a second run on a converged geometry moves **0.000000000**; and a full-selection run at every bundled size is unchanged (a 356-atom structure: 200 steps in 21 chunks, ~42 ms per ten-pass chunk).

### Added

- **A saved file now says where it came from and what was done to it** — The viewer wrote a structure out with whatever title the file happened to carry, or with "Modified structure", so a saved geometry arrived detached from its history: the file it was taken from, the step of a trajectory it was cut at, and the edits that produced it (deleted atoms, a translation, an optimisation, a normal-mode displacement) were nowhere in it. Every format that owns a title or comment line now carries one line of provenance, built from what actually happened: `MV: from opt.log, frame 12 of 40, Step 12; 2 atoms deleted, translated, displaced along mode 7 (38.2 cm-1) +0.45 A`. It names the **source file**, the **frame** of an optimisation trajectory (with that step's own label when the log carries one) or the molecule of a VMD script, then the **edits in the order they were made** — atoms added/deleted/replaced, hydrogens added, translated, rotated, bond length/angle/dihedral adjusted, MM-optimized, disorder removed, files merged in, supercell bounds — and finally any **manual normal-mode displacement**, with each mode's number, its frequency (an imaginary one marked `i`) and its amplitude. Every clause is recorded at the operation that performs it instead of being inferred from the coordinates at save time, because "was this edited?" cannot be read off a structure; and the record travels in the **Undo** snapshot, so undoing an edit takes its clause off the title together with the geometry. **Restore initial** on a Molecular Mechanics run takes the optimisation clause back the same way.

  The line goes wherever the format can hold one — the XYZ comment, the Gaussian title card, the MOL2 molecule name, the MDL title line (which used to be blank), a PDB **TITLE** record wrapped at 60 characters with PDB's own continuation number, the MOPAC title, an ORCA comment line above the keywords, and the POSCAR/CUBE/VESTA headers — while formats with no title line (Turbomole `$coord`, CIF) are written exactly as before. The file's **own title** is appended after a `|` only when it describes the structure on screen: a trajectory's title belongs to the geometry the file opens on — a log's title card is that first structure's comment, and a frame switch does not rewrite it — so saving frame 79 of a 79-frame log must not end with frame 1's `Step 1 (Charge=0 Mult=1)`, which says the opposite of the frame clause beside it; the same holds for a molecule list, where a molecule after the first does not claim the script's title. A **GJF keeps its own title card**: the provenance line is written first and the original title lines follow it verbatim, so nothing the user wrote is lost, while lines an earlier save wrote are filtered out, so a file the viewer produced can be saved again without provenance stacking on provenance (the same `MV: ` marker makes the original-title tail drop itself when it is one of ours). The wording is deliberately short and **ASCII** (`A`, `cm-1`): a Gaussian title card is read by programs that are happier without non-ASCII, and a displaced structure's "Å" is no reason for one. The line is capped at **190 characters**, where whole clauses drop off the end behind a `...` rather than being cut mid-word, and a long original title is the part that gives way first.

  Implemented as one module: a state block (source file, merged files, edit list, committed displacements) declared beside the view state so no early path can read it undefined, the formatter beside `doSave`, and one `provMark(...)` call at each place that changes the geometry or the atom list — seventeen of them, from the four atom-edit dialogs to an Alt-drag, a Rotate Group commit, an MM run, a frame switch and the displacement slider. Verified by cutting the real code out of the compiled page and driving `doSave` against a stub host — **61 assertions**: the title each of XYZ / GJF / MOL2 / MDL / PDB / MOPAC / ORCA is actually written with, frame and step labelling, counted edits merging (three deletions read as one clause), the order of clauses, imaginary frequencies, a live versus a committed displacement (a committed one survives the session that made it), undo removing exactly the clause it undoes (and the snapshot being a deep copy, not a reference), an import naming its file once, a GJF keeping its own title lines with no duplication on a round trip, PDB wrapping, the 190-character cap and what it drops first, the supercell clause read from the bounds rather than marked, and a source-less structure falling back to the file it was merged from. The wiring is pinned by extracting each commit point's own source and looking for its mark — a formatter-only test would pass with the marks missing — **18 such checks**, the four atom-edit dialogs and the three geometry dialogs included.

- **Manual Displacement writes normal modes into the coordinates, as a combination** — The Modes panel could play a vibration but not hold it: the playback borrowed the geometry for one sine cycle and put it back, which left no way to inspect a distorted structure — its bond lengths, its angles, its shape — or to keep it. A mode now carries **two separate selections**, one per half of the feature. The **circle** at the end of its row picks that mode for the displacement slider; the **row itself (or its ▶)** plays the vibration. They are independent on purpose: playing a mode no longer re-aims the slider, and picking a mode no longer starts a playback — so a mode can be watched without disturbing what the slider will write, and a mode can be picked for displacement without an animation running over it. The block names the picked mode, its circle stays filled, and the row currently carrying a displacement is marked with the orange edge whether or not it is the picked one. The panel then carries a **Manual Displacement** block: with a mode picked, drag the slider and the structure is set to `equilibrium + Σ (scale_k × mode_k)` on every move. **A mode is added to the distortion, not swapped for the previous one** — the normal modes of one frequency job are an orthogonal basis of the 3N-6 displacements (orthogonal under the mass-weighted inner product the printed vectors already carry), so the sum is exactly a point in normal-coordinate space, and displacing along a second mode is the same arithmetic as a scan along a line in that space. Nothing accumulates invisibly: the block lists every component (`#2 +0.50 · #1 +0.30`), every contributing row carries the orange edge, dragging a component back to 0 takes that mode out, and Reset clears all of them. The largest displacement of the *combination* is measured on the result and shown next to the list, because it is not the sum of the parts — two modes can partially cancel. The slider itself is a **proportion of one mode, from −1.00 to +1.00**, not a distance: 1.00 moves that mode's most-moving atom by 1 Å, every other atom by its own share, so the same number means the same amount of the same mode on any structure, and each mode's relative per-atom weights and phases are kept exactly as the calculation produced them. The block prints what the picked mode's share comes to next to it (`+0.50 · max 0.50 Å`), so the number is never the only thing on offer. Each write starts from the equilibrium snapshot taken when the session opens — never from the previous frame — so dragging back and forth cannot accumulate drift, one slider value always means one geometry, and a repeated event (`input` + `change`, a key repeat) writes nothing at all; a value that arrives outside the range (a programmatic call, a hand-edited message) is clamped instead of written. **Save As** writes the displaced geometry in any format, and the dialog states the composition it is about to write instead of leaving the modes to be discovered in the file.

  Three states are kept apart so a *pose* can never be mistaken for a *structure*. `vdBase` is the equilibrium the offsets are measured from; `vdComp` is the list of components actually in the structure, each with that mode's unit displacement; `vdTarget` is the mode the panel points at, whose share the slider edits — so picking or watching a mode writes nothing, and only a slider move adds a component or changes one ("Drag to add this mode to the distortion", "In the distortion: drag to change its share, 0 takes it out"). A session is a **pending rewrite of every atom**, which is why arbitration is the feature's other half: `pushUndo` — the door every coordinate edit opens with (bond length / angle / dihedral, add / delete / replace atom, batch delete, Add H, Import, Rotate Group, Move Atoms, Alt-drag, a Molecular Mechanics run) — closes the session first and keeps the geometry it produced, so the edit starts from the distorted structure and its own snapshot captures that structure; a frame switch, a molecule switch and an Undo drop the session instead, because the structure it was measured from is gone; a live Molecular Mechanics run refuses the slider and says so (the run owns those coordinates), and a Move Atoms session is committed before the slider takes over. **Reset** removes every component, writes the equilibrium back exactly and takes the session's undo snapshot with it, so a distortion that is undone leaves the stack as it found it; dragging the last component back to 0 does the same.

  The playback is the deliberate exception, and it is what makes the two usable one after the other. A manual displacement is a structure, a playback a pose: playing any mode swings from the session's **undisplaced** equilibrium — never from the distorted atoms, and never from the other components either — and stopping writes the whole combination back. So a mode always animates the motion the calculation produced rather than that motion on top of an arbitrary offset, watching modes never costs the distortion, and the user can drag, watch, come back and drag again. Without a session the playback is exactly what it was.

  **This is a restrained optimisation, not an isolated one**: a fixed atom is a full participant in every term it shares with a mobile atom — its bonds, angles, torsions, impropers and non-bonded contacts all pull on the selection — and only a term whose atoms are *all* fixed is dropped (it cannot change and would only add a constant). That includes the case a terminal group hangs off a frozen backbone: a dihedral's energy depends on all four of its atoms, so its term is live as soon as *any* of them is mobile, including a mobile flanking atom on a fixed central pair. The contract `evaluateForceField` hands out matches: `gradient[i]` is exactly zero for a fixed atom and non-zero for a mobile one that shares a term with it.

  The force field (`src/tools/mmOptimizer.ts`, one module, zero dependencies) takes its reference geometry from the plugin's own experience tables — `empiricalBondLength`, `empiricalBondAngle`, `empiricalVdwRadius`, the same windows Add H reads and the same numbers the SMILES → 3D engine projects its generated structures onto — so a relaxed bond is the bond generation would have produced. **Bond stretch** is harmonic with `k = 664.12·Z₁Z₂/r₀³` over effective charges and the table's `r₀` for the bond's order (aromatic bonds go through the table's aromatic entry, so benzene relaxes to 1.386 Å). **Angle bending** is harmonic towards the centre element's own theoretical angle (C 109.47° sp³ / 120° sp² / 180° sp, N 106.5°, O 104.5°, S 98°), read off the bond orders the centre already has the way the engine reads them; the window in which the term exerts force is **asymmetric** — a *compressed* angle beyond 30° of its target carries none, so a strained ring (cyclopropane's 60° internal angle) is left as drawn, while a *widened* one keeps pulling up to 60°, because an angle that is too open is a drawing to be corrected rather than a clash to be left alone. **Torsion** is three-fold staggered on an sp³–sp³ bond, two-fold planar where an sp² centre or a double/aromatic bond is involved — where a double bond's two-fold term makes cis and trans *both* minima, so it can straighten a group but never flip it inside out — and no term at all where hydrogen defines the four-atom set, which leaves a methyl group's rotation free and restrains only a chain's backbone and a planar group's conjugation. **Out-of-plane** restraints hold a three-coordinate sp² centre planar using the signed volume of its three bond vectors, scaled by a fixed reference area so the energy of a given out-of-plane height does not depend on the centre's own bond lengths. **Non-bonded** is Lennard-Jones with σ from the van der Waals radii and ε = 0.044–0.21 kcal/mol, excluding bonded pairs, a 1-4 pair at half strength, no charges, and switched off smoothly between 6 and 8 Å — a bare cutoff leaves a step of the pair's energy at the boundary (≈6e-4 kcal/mol), and a pair crossing it makes the energy discontinuous, which a line search cannot step through. Below 0.2 σ the potential is continued by its own tangent, so a pile-up of atoms stays finite (no Infinity, no NaN) while still being pushed apart. A **1-3 pair that comes inside 0.45 of its van der Waals sum is re-admitted as pure r⁻¹² repulsion**: an angle squeezed that far sits in the angle term's force-free window, and without this guard two neighbours can walk onto each other (see the verification below — that collapse was found and fixed by test, not by inspection).

  **Only the terms a mobile atom takes part in are evaluated** and the optimiser is a preconditioned Polak-Ribière conjugate gradient whose every accepted step must lower the energy, so a run is monotone by construction and the geometry it returns is never worse than the one it was given, converged or not. Two properties make the search able to walk down at all, both established by measurement: the step cap is a **trust radius on the whole direction** (the preconditioned vector is scaled so its largest atom step is the cap) rather than a per-atom clip — a clip decouples the trial from the line-search factor, so every attempt moves the clipped atom by the same distance and a step whose curvature cost exceeds its gradient gain can never be shrunk; and the **pair list is rebuilt only after an accepted step**, once an atom has drifted 0.5 Å, and the energy the next search compares against is re-evaluated from that list — rebuilding from a trial geometry would leave the search comparing energies from two different lists, which looks like a step-independent jump (the clash guard's membership depends on distance, and its energy is large). The whole call is bounded by atom count (3000), step count (500) and wall-clock time (5 s), and the geometry returned when a budget runs out is the best one found.

Enter the mode, click atoms (or carry a selection in from Select Atoms / Box Select / Replace Atom), click the button again and the hydrogens are placed; one **Undo** step reverts the whole addition, and re-running it on the completed structure adds nothing.
  The numbers are the SMILES → 3D engine's own (`empiricalValence`, `empiricalBondLength`, `empiricalBondAngle`, `empiricalVdwRadius` — four thin windows opened on `smilesTo3d.ts`, whose tables and code paths are untouched), so the chemistry cannot drift from the geometry the engine generates: **S completes to 2 and P to 3**, a C–H bond is 1.09 Å, N–H 1.01, O–H 0.96, S–H 1.34, P–H 1.42, and the angles are the element's theoretical ones (C 109.47° sp3 / 120° sp2 / 180° sp; N 106.5°, O 104.5°, S 98°). The centre's hybridization is read off the bond orders it already has the way the engine's own pass reads a bond list — a triple bond is sp, two double bonds on a two-coordinate centre are sp (cumulated), a double or an aromatic bond is sp2, an amide-like nitrogen next to a multiple bond is sp2 — so a ring carbon with two aromatic bonds gets its hydrogen in the ring plane at 120°, a methyl group comes out tetrahedral, an alkyne's hydrogen linear, and a nitro nitrogen (valence 6, above its empirical value) is reported rather than completed.
  The directions are found in two steps, and only the hydrogens ever move: a deterministic greedy start (each hydrogen takes the direction farthest from every bond already present and every hydrogen placed before it), then Gauss-Seidel projection of the angle constraints onto the element's theoretical angle. An sp2 centre additionally has its hydrogens projected onto the plane of the bonds already present — a coplanar direction is an extremum of every angle around such a centre, so the solver converges on the angles long before the out-of-plane component, and a residual of a few hundredths of a degree would otherwise show up as a hydrogen a tenth of an Ångström out of the ring plane. A final pass rotates a hydrogen out of the way when a non-bonded atom sits closer than 0.62 of their van der Waals sum (each rotation is about the centre, so the X–H length stays exact — verified to 1e-9 Å even after a clash adjustment), trying several step sizes in both senses so a hydrogen between two atoms moves to the larger gap rather than oscillating. A hydrogen that would still sit closer than **0.80 Å** — shorter than the shortest real bond (H–H, 0.74 Å) — of an atom it is not bonded to is **left out** and reported, so a structure with two centres a fraction of an Ångström apart (a coordinate defect, not chemistry) cannot smuggle an atom overlap into the viewer through this operation.
  The geometry is computed in the extension host, where the engine lives, in one round trip that mirrors Import Structure (the request carries the structure as it stands in the view, edits included; the answer carries only the hydrogens), and the client applies it through the same undo/rebuild path every other edit uses. Guards: a periodic structure and a two-structure comparison refuse the mode (a new atom has no place there), a click without a selection says so instead of guessing, and a second click while a request is in flight is ignored.
  Verified with the real host module and the real client code driven against stubs. Geometry: water comes out 0.96 Å / 104.5°, ammonia 1.01 / 106.5°, methane 1.09 / 109.47°, H2S 1.34 / 98°, PH3 1.42 / 100°, HF 0.92, an ethane fragment's three hydrogens are tetrahedral to 0.15° in every one of the six angles, benzene's hydrogen lies in the ring plane to 0.01 Å at 120° to both ring bonds, an amide nitrogen's hydrogen is planar at 120° where the same skeleton without a multiple bond stays pyramidal at 106.5°, an alkyne's hydrogen is linear to 0.15°, and an isolated hydrogen completes to H2 at the clamped 0.70 Å. Cross-checked against the engine itself: ethane generated from `CC` has every C–H at the table length and every H–C–H at 109.47°, and completing the same skeleton reproduces both. Corpus smoke over 14 test files (564-atom PDB down to water): only hydrogens are ever returned, every new X–H bond equals the table length to 1e-9, no placed hydrogen comes within a bond length of any atom it is not bonded to, re-running on the completed structure adds nothing, and the input arrays are never mutated. Robustness: `undefined`, wrong-typed records, out-of-range and fractional selection indices, a missing element, NaN coordinates, self-bonds, duplicate bonds, negative and NaN orders, coincident atoms and a collinear centre all return a structured result in bounded time without throwing, the answer is deterministic (one structure, one answer), and a pathological selection cannot exceed 5000 hydrogens per call — the budget itself is reported. Cost: a 216-atom PDB completes in 1–2 ms, a 629-atom one in 3 ms, a 2000-atom chain with 4002 hydrogens in **188 ms** (best of 3, on an absurd geometry whose angle targets are geometrically impossible), and the 2000-atom budget case places 5000 hydrogens in 68 ms. The client chain was checked on the extracted script: it parses, the listener and the helpers are wired in an order that survives `var` hoisting, the request carries a copy of the structure, a malformed answer cannot write a bad bond or throw, and a full host→client round trip adds exactly the hydrogens the host returned while the pre-existing atoms stay byte-identical.

- **A valence solver is now available for structures the length table cannot settle — off by default** — Order assignment itself is unchanged: each bond length is read against the per-element-pair table of (order, length, tolerance) entries, the order is snapped onto a value the pair allows, and the local relaxation takes excess off over-coordinated centres. What is new sits around that, and the first three pieces cannot change a single bond the viewer already drew.
  - **Formal charges.** Every atom's formal charge is derived from the orders the geometric pass produced (`PerceptionResult.charges`, from the element's outermost-electron count and its total bond valence). Pure addition: it reads the finished bonds and writes nothing.
  - **An off-valence report.** `diagnostics.offValence` lists the atoms whose valence is not one their element may take, counted **in both directions** — a carbon at 3.5 is listed, and so is a nitrogen at 5. A ceiling comparison passes the first and mistakes the second for an ordinary amine, which is why the report uses the element's allowed valence set instead.
  - **A count of what a solver could do.** `diagnostics.repairable` says how many connected components are still off their allowed valence, so a caller can see what is on offer before asking for it.
  **Then, opt in** — `perceiveBonds(atoms, { solve: true })` — a valence-conservation solver takes over exactly those components: every atom is given a target valence from its element's allowed set (N 3 or 4, O 2/1/3, S 6/3/2/1), unsaturated atoms are paired by a maximum-cardinality matching until each reaches its target, and an assignment is accepted only when the formal charges it implies sum to the total charge the file states. It is off by default because it answers a **component-wide** question: it re-derives every bond in the component, so it moves bonds that were never in doubt — a ring comes back as an alternating single/double pattern until the aromatic restoration puts it right, and a bond beside a repaired centre is re-assigned to keep the books balanced. That is better chemistry, but it is a visible change the default has no business making on its own. On the bundled corpus it is the difference between 110 and 189 changed bonds.
  **Opting in cannot make things worse, and neither can leaving it off.** Two clauses, both run for **both** modes against the previous detector compiled from the same tree, over 16 structures and 2592 bonds. **(A) Atom level** — no file may end up with more atoms off their allowed valence, or a larger total deviation. All 16 pass in both modes: six improve (with the solver on, `dForce4.pdb` 244 atoms / 196.0 → **184 / 160.0**, `1500752_2met.gjf` 34 / 17.0 → **4 / 2.0**, `732742_*.gjf` ×2 18 / 12.0 → **0 / 0.0**, `PEG600.gjf` 2 / 1.0 → **0 / 0.0**) and the rest come out byte-identical. **(B) Bond level** — every bond whose length fit got *worse* must belong to a connected component the old result already had a valence problem in. Default mode: 110 bonds change, 98 with a worse fit, **0 unattributed**. Solver mode: 189 change, 166 worse, **0 unattributed**. A runtime **safety valve** backs the same property up on inputs the corpus does not contain — an answer is adopted only when it lowers the component's total valence gap and is otherwise rolled back — and the aromatic restoration moves only whole groups whose changes cancel exactly at every atom, so it cannot shift an atom off the valence the solver established. **Connectivity is untouched in both modes**: not one bond was added or removed anywhere. Benzene keeps its six 1.5 bonds, water its two single bonds, ethyne its triple bond; with the solver on, nitromethane comes out `N–O` = 1 and 2 with the nitrogen at valence 4 and a `+1` formal charge where the geometric pass left it five-valent. The pass is idempotent (16/16 on a second run). What remains are structures whose component exceeds the combination budget, or whose geometry is inconsistent to begin with — `ethane_distorted.gjf` places a hydrogen 0.908 Å from one atom and 1.083 Å from another, both inside their cutoffs, so its carbon is genuinely 3-coordinate and the solver correctly declines it.

- **VMD TCL scripts now render their whole display recipe, not just their colour groups** — Opening a `.tcl` used to read two things out of it: the file named by `mol new`, and `mol color ColorID N` + `mol selection "index …"` pairs, which were turned into per-atom colour overrides. Everything else the script says was ignored — representation styles and their arguments, `mol color Beta`/`Name`, `mol scaleminmax`, the display background, `color change rgb`, and any second `mol new`. The parser (`src/parsers/vmdVisualization.ts`) now reads the script as the display recipe it is: every `mol new` becomes a molecule with its own representation list, and each `mol representation <style> <args…>` / `mol color <mode> [arg]` / `mol selection <expr>` / `mol material <name>` / `mol addrep` becomes one representation carrying its style, numeric arguments, colour mode, colour argument, selected atoms, material and any explicit colour-scale range. `mol modstyle` / `mol modcolor` / `mol modselect` / `mol modmaterial` modify an existing representation, `mol delrep` removes one, and `color Display Background <name>`, `color scale method <name>` and `color change rgb <id> <r> <g> <b>` are read into the scene model (the palette overrides and colour-scale method are applied; the display background is deliberately not — see Changed). Comments, `{}`/`""` quoting, `\`-escaped spaces, Windows-style paths and continuation-free multi-clause lines are all handled (`mol new {my file.pdb}`, `mol selection "index 0 to 5 9"`, `not index …`). Representation indices follow the renderer's own bookkeeping, including the default representation `mol new` creates and `mol delrep 0 top` deletes — so `mol scaleminmax top 1 …` in a script that kept the default rep addresses the first added representation, exactly as it does in VMD. Atom selections are resolved against the loaded structure: `index` lists and `to` ranges (0-based, out-of-range indices dropped), `element` / `name` / `type` symbol lists, `not` negation, and `all` / `none`; a selection that needs residue metadata the viewer does not keep (e.g. `resname BIB`) is widened to the whole molecule **and reported** on the status bar and in the info panel instead of silently drawing the wrong atoms. All of this is applied when the script is opened *and* when it is used as the comparison side of Structure Diff, through one shared loader.
- **`Surf` representations are drawn as real solvent-accessible surfaces** — A `mol representation Surf <probe> <isovalue>` patch is no longer skipped: the viewer extracts the isosurface of `f(p) = min_i(|p − c_i| − (R_vdw,i + probe))` over the atoms that representation selects, by marching tetrahedra (each grid cube split into six tetrahedra, so there is no ambiguous-case table to get wrong). Patches are drawn translucent, because a script stacks many of them and opaque ones would hide everything except the outermost — which is why a script like `show_eggs.tcl` ends up as fourteen nested coloured shells around a ball-and-stick core. Each patch rides inside the molecule group, so it follows the view's rotation, panning and zoom exactly as the atoms do. Verified against independent invariants, not against itself: for a non-grid-aligned sphere the mesh comes out **closed** (every edge shared by exactly two triangles, 3168 edges, 0 unpaired), **free of degenerate triangles**, with a maximum radial error of **0.035 Å** at a 0.45 Å grid and an area within **5 %** of 4πR²; two overlapping spheres reproduce the analytic union area (114.50 Å² measured vs 115.36 Å² for spheres of R = 2.7 Å at 1.4 Å separation); the real `test/samples/A2_eggs` family (14 patches, 72 atoms) builds **163 872 triangles in 49 ms**, so a scene rebuild stays interactive. Geometry that lands exactly on the sample grid (a measure-zero configuration that real coordinates do not produce) can yield a handful of sub-nanometre sliver triangles — reported by the checks, harmless to the render.
- **Per-atom scalar (`Beta`) colouring, for scripts and for plain PDB files** — PDB columns 61-66 are not a B-factor in this toolchain: the visualization files write an arbitrary per-atom scalar there (a unit index, a per-atom force error, a difference between two rounds), and **the scalar is the visualization** — several sample directories ship the picture as a bare PDB with no TCL at all. The column is now parsed into `Atom.beta` (and occupancy from columns 55-60), and three things follow from it. A `mol color Beta` representation paints atoms on the reference renderer's RGB ramp, **as it is actually rendered** rather than as its scale nominally reads: red → green → blue with the midpoint at 0.5, but with the two passive channels sitting on a 15/255 floor and the active channel ramping at twice the nominal rate, so the rendered colours never reach pure (0,0,0) in any channel — the low end renders as `#FF0F0F`, the midpoint as `#0FFF0F`, the high end as `#0F0FFF`, and the active channel saturates before the leg ends (red is already fully saturated below t = 0.0294, green from t = 0.4706). The range used is the script's `mol scaleminmax` when it writes one and the actual data range of that representation's selection otherwise — so `show_units.tcl`'s un-scaled Beta rep ranges 0–26 by itself and spreads its 27 unit indices over 27 distinct colours, while `force_error.tcl`'s hardcoded `0 – 100` compresses the 0.04–3.92 force errors into the bottom 4 % of the scale (`#FF0F0F` … `#FA230F`), which is what that script really does. **A written range is treated as an unconditional statement about the column**: `mol scaleminmax` says the column *is* a scalar channel, so the colouring is applied even when every value in it is identical — `force_error_delta.3.pdb` is all zeros and its script writes −10 … +10, and the whole molecule therefore comes out on the middle of the ramp (`#0FFF0F`) instead of the low end. Only when a script leaves the range open does the layout come from the data. A structure opened **without** a script is painted by its own scalar straight away: a file is recognised as a bare coordinate file (nothing but `ATOM`/`HETATM`/`CONECT`/`TER`/`END`/`MODEL` records, no deposited-structure header) whose column is non-constant, which is exactly the shape this toolchain's visualization output has, so `xo_force.R2.5_force_error.pdb` (0.01–0.88), `force_error.1.pdb` (0.04–3.92), `a6_single.1.pdb`, `force_error_delta.2.pdb` (−3.70–1.23) and `C1c_with_beta_unitidx.pdb` (unit index 0–26) all open showing what they were written for. A deposited PDB — anything carrying a header record — is left in its element colours, and a constant column (the exports written with 0.00) colours nothing. The **Color by Beta** toolbar button is shown whenever such data is present, starts active when the colouring was applied automatically, and toggles it off again; the status bar reports the range in use. The colouring is also a pure **view state**: the scene build reads it per atom instead of painting `Atom.color`, so the stored colours stay canonical and no combination of edits, undo, import, frame stepping or molecule switching can leave a scalar colour applied to the wrong atom.
- **An egg list for scripts that draw eggs** — When a structure is opened through a script whose Surf patches match the toolchain's egg metadata (an `eggFile*` next to the structure naming each egg and the unit numbers it wraps — `U12F1 : 1,10-15` — plus a `unitfile` holding every unit's atoms), an **Eggs** button appears in the toolbar and a panel lists every egg: each row carries the egg's colour as a left accent bar, followed by its name and the unit numbers it contains, compressed into ranges (`units 1, 10–15`). All eggs are shown initially, and unchecking a row hides exactly that egg's surface patch (checking it brings it back), with a header counting how many are shown and a **Hide all / Show all** button that toggles every egg in one click (the label follows the state, and a partial selection is completed rather than reset). Hiding an egg survives scene rebuilds (edits, undo, rotation-centre changes) because the choices are keyed to the patch's position in the script; switching molecules or frames — which change the patch list — resets them. The metadata files are optional: a script without them renders its patches unlabelled, malformed files leave them unlabelled rather than failing the load, and an egg the script does not draw (a whole-structure `full` surface) is simply not listed.
- **A molecule selector for scripts that create several molecules** — `force_error.tcl` performs four `mol new` calls, one per optimisation round, on coordinates that describe the same system at different stages; VMD would superimpose them. The viewer shows one at a time and adds a ◀ n/N ▶ selector to the toolbar (next to the frame stepper) so the rounds — or `force_error_delta.tcl`'s three — can be compared directly; each molecule keeps its own representation list, its own colours and its own surface patches, switching clears the undo stack like frame stepping does, reframes the camera on the new structure, and is disabled in diff mode and for crystal structures.
- **Measured reference palette and radii** — The `ColorID` table was a set of approximations; the entries that could be measured (blue, red, gray, orange, yellow, tan, silver, green, white, pink, cyan, purple, lime, mauve, black, yellow2) now carry the reference renderer's actual RGB — notably `cyan` is the soft `#40BFBF`, not `#00FFFF`, which is the colour `mol color Name` gives every carbon. `mol color Name`/`Element` resolves elements through the reference renderer's element colours (C cyan, H white, N blue, O red, S yellow, P tan, halogens green, alkali metals purple, alkaline earths green, other metals silver, Br brown, I purple), van der Waals radii are tabulated per element (H 1.00 Å, C 1.70 Å, …) with a 1.50 Å fallback, and a `Licorice`/`Lines` representation draws sticks without spheres while a `VDW` one draws spheres without sticks.
- **SMILES import (Import Structure → From SMILES)** — The **Import Structure** button now asks where the structure comes from before opening anything: a source dialog (whose input box carries the copy count — see Changed below) offers **From File** (unchanged behaviour — file dialog, multi-frame picker, crystal handling) or **From SMILES**, which opens an input box that validates the string **on every keystroke** with the engine's own lightweight check (parse → implicit hydrogens → valence, no geometry stage; measured 0.11 ms on a 288-character string, so typing stays interactive) and shows the engine's own error message — position included, e.g. `位置 3: 非法字符` or `括号不匹配 (未闭合的 '(' 共 1 个)` — inline in the box until the input becomes valid. Pressing Enter generates the 3D structure and posts it through the **existing** `importResult` path, so placement (bounding-sphere separation), the per-import undo snapshot, camera zoom-out, bond merging and Save As behave exactly as for a file import; cancelling either prompt restores the status bar like any other cancelled import. The generator is a complete **zero-dependency TypeScript port** of `test/smiles_to_3d.py` (`src/tools/smilesTo3d.ts` — element tables, SMILES parser, hydrogen/valence layer, ring perception, hybridization, spanning-tree placement, distance-constraint relaxation, dihedral enforcement, chirality, plus `validateSmiles` / `smilesTo3dSafe` / `toXyz`), section-for-section faithful to the Python original. Aromatic bonds are imported with order **1.5** (the convention the MOL2 parser already uses for `ar`), so benzene renders as 1 solid + 1 dashed line instead of six single bonds and exports back as aromatic in MOL2/MDL; bonds coming from SMILES are authored, so the imported part keeps its orders instead of being re-detected. Verified against the Python reference on **67 cases** (drug molecules, aromatics, fused rings, `%nn` ring closures, isotopes, charges, salts, wildcards, stereocentres, cis/trans-marked double bonds, and 12 invalid inputs): identical atom counts, bond lists, ring lists, formulas, fragment counts, total charge and stereo parity in every case, all 12 invalid inputs producing **byte-identical** error code + position + message, and a maximum coordinate deviation of **2.5e-12 Å** (max bond-length deviation 1.7e-13 Å). End-to-end simulation of the host → webview chain confirms import into an empty view centres at the origin, importing beside an existing structure leaves its atoms and bonds untouched while offsetting the imported bond indices correctly, repeated imports never overlap, multi-fragment input keeps its separation (`[Na+].[Cl-]` → 4.0 Å), and 32 malformed/hostile inputs (empty, non-string, unbalanced parentheses, unclosed rings, non-ASCII, 40 000-character strings, a 4502-atom input over the cap) all return structured errors without throwing or hanging

- **Diff: grouped internal-coordinate statistics (n / rms / maxd / mean / std)** — When two structures pass the skeleton check, the Diff panel now shows a collapsible **Internal Coordinate Statistics** block above the difference list: for bond lengths, bond angles and dihedrals it reports **n, rms, maxd (max |Δ|), mean and std** for every element-composition group (e.g. `C-C`, `C-C-H`, `C-C-C-H`) plus a combined **All** row, so a whole comparison can be read at a glance instead of by scrolling the itemised list. The statistics cover **every compared coordinate**, not just those above the display slider, so they are independent of the threshold — verified: identical values at 0 / 0.0001 / 0.5 / 20 % while the listed differences went 10 / 30 / 28 / 0. Values are signed differences (left − right), a torsion's difference folded into [−180, 180] so a chain and its reverse can never disagree; rms is √mean(Δ²), maxd = max|Δ|, mean = mean(Δ) and std the population standard deviation, printed in Å to 4 decimals for lengths and in degrees to 3 for angles and dihedrals. Groups are canonicalised — bonds and angles by their two outer elements, torsions by the four elements along the chain, reversed when the tail sorts before the head — so one coordinate always falls in the same group however the atoms are numbered and whichever direction the enumeration reached it from (verified by renumbering benzene: every group and total came out identical). A comparison that matches but shares no bond, angle or torsion says so per kind instead of printing an empty table. The block collapses when its header is clicked, and the expanded/collapsed choice survives the re-render that every threshold-slider move triggers. Correctness was checked against an independently written enumeration of the same three coordinate kinds on ethanol, a perturbed benzene ring and a 24-atom two-fragment benzene dimer — every group and total agreeing to 1e-9 — against the analytic answer for a uniformly scaled ring (per-group bond rms/mean/maxd/std exact, angles and torsions left at zero to 2.8e-14), and at the rendering level (units, column headers, All rows, empty-case text, non-finite formatting)

### Changed

- **Format readers and chemistry engines now live in separate source directories** — `src/parsers/` had collected five modules that read no file at all: the bond perception engine, the `ensureBonds` entry over it, the zero-dependency SMILES → 3D generator, the hydrogen-completion pass and the molecular-mechanics force field. Each takes a structure in and gives a structure back, and each is reached from the editor rather than from the format dispatcher. They now sit in `src/tools/`, beside `src/parsers/`, which keeps exactly what its name says: the dispatcher `index.ts`, the fourteen `*Parser.ts` modules, and `vmdVisualization.ts` — a VMD script being one of the supported input formats. The boundary is the direction of the data rather than a file count: `parsers/` turns text into a molecule, `tools/` turns a molecule into another molecule. The move itself touched six import lines in two files (`extension.ts`, `webview/molecularViewer.ts`); no module body, public API, table or serialised source changed, `tsc --noEmit` is clean, and the compiled output differs only in the paths it requires. The stale copies the compiler leaves behind under `dist/parsers/` were removed, because `tsc` does not delete output for a module whose path has changed.

- **The release workflow now points Latest at the newest eligible build rather than at the branch that triggered it** — GitHub refuses to make a pre-release the latest one ("Latest release cannot be a draft or prerelease", HTTP 422), so a build published as a pre-release can never carry the badge, and the badge used to be set on `main` alone. The job therefore ends with a step that lists the published releases, takes the newest that is neither a draft nor a pre-release, and points Latest at it — so the badge always tracks the newest build that can hold it, whichever branch produced it, and re-asserts itself after a rerun, a back-fill or a channel correction. Whether the `developing` channel is published as a pre-release is now a single workflow-level switch, `PRERELEASE_ON_DEVELOPING`: at `"true"` that channel keeps its pre-release marking and the badge stays on the newest stable release, while at `"false"` both branches publish as ordinary releases, which makes the newest build from either branch the latest and puts it at the top of the release list. A `developing` build carries its pre-release nature either way through its `<version>-<hash>` number, its release title and notes, and the `.vsix` itself being packaged with `vsce --pre-release` — the release-level flag and the packaging flag are now decided separately. Publishing also no longer demotes a release that is currently Latest when a `developing` rerun happens to share its tag, which is the one path by which a stable build could lose the badge to the branch that produced it, and the job summary reports the resulting Latest tag.

- **The webview no longer keeps its own copy of the bond detector** — The client carried a hand-maintained duplicate of the detection tables, the order assignment and the valence pass, and it had already drifted: its Move Atoms path still held the retired hardcoded `C–O`/`Br` whitelist and the nitrogen special case while the host detector had moved on to the table-driven, reversible pass, so moving an atom could produce orders a fresh load of the same coordinates would not. The host now serialises `bondPerception.ts` into the page as `BP` — its tables as JSON, its functions as their own source text, all in one scope — and the client's `detectBondsFromAtoms` is a one-line call into it, taking the total charge as an argument rather than reading it off the document (a re-detection does not always concern the structure on screen: the diff's comparison side is a different file). The source is checked for template-literal delimiters before it is emitted, because one backtick or dollar-brace anywhere in it — a comment included — would silently truncate the script it is embedded in. Verified by evaluating the template the way the host does (not by reading its raw text: the source escapes quotes for the template, so a raw slice is not valid JavaScript and reports failures that do not exist) and then asserting that the bytes the page receives are **identical to the module source** (40457 of 40457 characters), that the client script parses, that the perception entry point is present, and that the retired helpers leave **no reference** behind. The page grows by about 35 KB (287 KB to 322 KB).

- **Move Atoms re-derives whole connected components instead of a neighbourhood** — The release pass used to rebuild the moved atoms' region through that private copy of the repair rules, which is how it drifted from the detector. Only the selected atoms changed position, so connectivity — and with it every bond order — can only differ inside the connected components that contain them; those components are now re-derived whole with the same perception module the host used to load the structure, and everything outside them is kept untouched. Whole components and not a neighbourhood: the module's valence pass and its aromatic restoration both reason about a component as a unit, so handing it a fragment would ask it a different question than the load did. Verified against the strongest invariant available — the result must equal a full perception of the moved coordinates — over **nine scenarios** spanning one and three moved atoms, a single-molecule file, a crystal-derived PDB and the 564-atom structure: every one **identical**, including a benzene atom dragged 3.0 Å away and a methane hydrogen dragged 2.5 Å into isolation. An empty selection returns immediately, and a selection that produces no change in any bond reports nothing to rebuild.

- **All visualization-file handling now lives in one module** — The TCL script parser and the palette/representation resolver were two files that only ever worked as a pair (the parser imported the palette, the resolver consumed what the parser produced), and the test that recognises a bare scalar-carrying coordinate file sat inside the PDB parser, which is not what that parser is about. They are now one module, `src/parsers/vmdVisualization.ts`, laid out in the order the data flows: the reference renderer's palettes and radii, then the resolution of a parsed script into per-atom/per-bond drawing properties and surface patches, then the parsing of the script itself and the recognition of a bare scalar file. `tclParser.ts` and `vmdStyle.ts` are gone, `pdbParser.ts` is back to parsing PDB records, and the public API is unchanged (`parseTcl`, `resolveVmdScene`, `resolveSelection`, `vdwRadius`, `scalarColor`, `hasScalarChannel`, … are all re-exported from `src/parsers/index.ts`), so nothing outside the module had to change beyond its imports.
- **TCL structures keep their ball-and-stick geometry, with the script's *relative* sizes** — A script's representation arguments are relative to the reference renderer's own defaults, not absolute radii for a different drawing style: `CPK 1.0` there means van der Waals spheres (a space-filling model), which would turn every structure into one solid blob and hide the bonds, the segmentation and the whole point of the picture. The viewer therefore applies the script's **ratios** to its own geometry: sphere radius = the viewer's own sphere radius × the script's sphere scale (so `CPK 0.97` and `CPK 1.0` come out the same size as an ordinary structure, the force-error scripts' `CPK 0.7` comes out smaller, and `CPK 0.1` comes out tiny), and bond radius is rescaled the same way against the reference default of 0.3 (so `CPK … 0.3` is the viewer's usual stick thickness, `0.1` a thinner one, and `Lines` a thin line). Sphere-segment counts stay the viewer's level-of-detail. What is *not* scaled down is anything physical: a `Surf` probe radius is an Å value and stays one, and the isosurface it produces sits that far outside the van der Waals surface, which is what makes a `show_eggs.tcl` picture read as coloured envelopes around the atoms. Atoms and bonds that **no representation covers are still not drawn at all** (a subset selection shows a subset; a molecule with no representations at all shows normally), and where two representations nest, the one drawing the larger sphere decides both size and colour — which is what makes one atom appear the way it does in the composited image.
- **The viewer keeps its own 3D background** — A script's `color Display Background white` is a setting of the reference renderer, and the viewer deliberately does not apply it: a white canvas clashes with the editor theme and washes out white atoms (which is exactly what `mol color Name` gives hydrogen). The directive is still parsed and recorded in the scene model, it is simply not a display parameter of this viewer; scripts that do not set one were already unaffected. Everything else about the palette *is* applied, including `color scale method` and `color change rgb <id> <r> <g> <b>` overrides.
- **One loader for every way a structure can be opened through a script** — The open path and the diff path had grown separate copies of the same "read file → pick a frame → detect bonds → handle crystals" sequence; there is now a single `loadStructureFile` plus `loadTclScene`, which loads every molecule a script refers to, skips the ones that cannot be read **with a warning instead of failing the whole script**, and makes the first loadable one the document's structure so Save As, Diff and the editing tools keep operating on a real coordinate file. The legacy per-group colour list (`parseTcl().groups`) is still produced and still documented, but a script that resolved into a scene is coloured by the scene. Switching frames of a multi-frame log reached through a script clears the script's surfaces and molecule list, because the recipe was resolved against the coordinates the script loaded and no longer describes the frame on screen.

- **A final pass looks at every atom's valence and fixes what can be fixed for free** — Once the orders are settled, each atom whose valence is not a value its element may take gets one more look: the orders of the bonds around it are re-arranged, and the change is kept only when the whole neighbourhood comes out strictly better. The measure is the one the diagnostic already reports — the total distance of an atom's valence from the values its element may take — and *better* means it improves **while the bond lengths fit no worse**, so a repair that fixes a valence by dragging a bond off its length is rejected on the spot. That conjunction is what makes the pass safe to run unconditionally: it cannot leave a structure worse, because refusing to is the rule it applies.
  Two constraints keep it small. **Hydrogen is pinned** — a hydrogen has one bond and its order is 1, so every bond to a hydrogen is held fixed, which takes a large share of the bonds in a typical structure out of consideration entirely and spares the pass from ever reconsidering a valence that was never in question (946 such bonds verified unchanged across the corpus). And **one neighbourhood at a time** — a centre and the atoms it bonds to, never beyond. Candidates are filtered to values that fit the length at least as well as the current one *before* any enumeration, so a structure where nothing can be improved — every centre off its valence for a reason no re-arrangement can fix — collapses each bond to one candidate and skips the work rather than exploring it.
  Effect on the bundled corpus, counting atoms off their allowed valence: **184 → 97** on `dForce4.pdb`, **24 → 4** on `1500752_2met.gjf`, **28 → 12** on `1873512_2met.gjf` and on `test.pdb`, **8 → 6** on each `732742_*.gjf`. The cost where it finds nothing is close to zero: a 200-atom chain stays at **0.8 ms**, 2000 atoms go 4.6 → **5.6 ms**, 8000 atoms 16.3 → **23.5 ms**, and the whole 16-file corpus is **23 ms**. Idempotence, the host/client agreement and the hydrogen pin are all re-verified, and the total valence gap is checked not to rise between runs.

### Changed

- **Move Atoms now checks whether anything changed before re-deriving** — The release re-derived the whole connected component containing the moved atoms. That is the right unit for correctness, but on a single-molecule file a one-atom nudge therefore cost a full re-derivation: measured at **23 ms** for a 2000-atom chain and seconds for a dense one, against a few milliseconds for the local repair it replaced. It now runs a cheap test first. A bond whose current order is still the order its own measured length supports cannot come out different, and a move only changes the distances from the moved atoms outward — so if none of their bonds has left its band and no new pair has come inside the bonding cutoff, there is nothing to re-derive and the component walk is skipped entirely. Measured: a 2000-atom chain drops from **6.8 ms to 1.0 ms** per release, and all **249** tiny nudges across the corpus take the fast path. A drag that genuinely changes the chemistry still falls through to the full re-derivation, and the fast path's answer was checked against a full perception of the moved coordinates on every corpus structure — **14/14 identical**, along with 11 releases that did take the slow path. Dense non-physical inputs (each atom bonded to dozens of others) see no gain, because the neighbour sweep that the check needs is itself expensive at that density.

### Fixed

- **A coordinate defect could turn the bond pass into an all-pairs blow-up** — Nothing rejected a pair of atoms sitting on top of each other: every entry in the element-pair table has an upper distance and none had a lower one, so two atoms at distance 0 bonded, and a structure of n coincident atoms bonded to all n-1 others. That gives a bond map of n² entries and, in the relaxation, an all-pairs search around every atom — a 3000-atom pile-up **did not return at all**. There is now a floor: a pair closer than **0.4 Å** cannot be a bond. That is below the shortest real bond (H–H at 0.74 Å), so no genuine structure is affected — the corpus comes out byte-identical with it — while a pile-up now simply has no bonds and returns at once (`3000 coincident atoms` went from "never returns" to `bonds 0` in milliseconds, and the same input with the solver on completes too). The floor is written as `!(d >= MIN)` rather than `d < MIN` so that a NaN coordinate is rejected as well, which is the treatment the ceiling already gives it.

- **A missing element symbol threw from the middle of a whole-structure pass** — `bpNorm` called `charAt` on whatever it was handed, so a single atom without an `element` string aborted the entire perception instead of being treated as an unknown element. It now returns an empty symbol for anything that is not a non-empty string, which degrades exactly the way an unrecognised element does: no table entry, so the generic fallbacks apply and that atom simply contributes no specific chemistry. Found by a test whose own fixture was malformed — the pass had never been handed one before.

- **The bond relaxation re-scanned every atom on every round** — The pass that brings over-coordinated centres back inside their valence ceiling walked the whole atom list each round. That cost was invisible while the pass could barely repair anything (it found no accepted plan and stopped after one round), but once an over-coordinated centre can actually be brought down it keeps finding work — and on a pathological input, a few thousand atoms clustered inside bonding range, the cost goes as rounds x atoms: a 2000-atom cluster measured **4.69x** the previous detector's time (866 ms to 4.06 s) while the real corpus moved by 1.12x. It is a **worklist** now: only a centre that is off its valence, and a neighbour an accepted plan has just moved, is ever examined, so the cost follows the atoms that need attention rather than the size of the structure. The same input measures **1.17x**, the bundled corpus **1.23x**, and a regular chain with nothing to repair **1.01–1.06x**. The number of examinations is capped as well, so a degenerate input cannot make the loop unbounded. **Results are unchanged** — the pass is a fixed-point iteration, so the visiting order cannot affect where it settles: every corpus result is byte-identical, idempotence is still 16/16, and the monotonicity gate reports the same numbers in both modes. Two smaller allocations went with it: the order snap no longer builds an intermediate pair list, and the component walk no longer builds a neighbour array per atom (the connectivity grid still does, where the sort is what makes the result order-independent).
- **The local relaxation could never lower a centre's total valence** — Both of its search phases only ever generated plans that left the centre's total where it was (one neighbour up, another down, by the same amount) and the acceptance rule required the total not to fall, so a centre above its ceiling had nothing to reach for: every plan on offer still added up to the same over-large sum. The amide nitrogen whose `N–C` measures inside the pair's aromatic tolerance — 1.33 Å falls in the 1.30–1.41 Å band the table carries for aromatic C–N — is the common case: it sits at 3.5 on a single bond and a half, and no rearrangement of its neighbours could bring it down. A centre that is already off its allowed value is now offered single-neighbour moves as well, which is the only plan shape that changes the total; a centre that is not over its ceiling keeps the old strict rule, so the sweep stays idempotent and still cannot invent a multiple bond out of a long contact. This is what took `dForce4.pdb` from 204 to 120 and `test.pdb` from 8 to 3.

- **Hydroxyl O–H bonds were turned into double and triple bonds, and the valence pass could only ever downgrade** — Bond-order assignment ran in four stages: geometry (element-pair table with a tolerance, else a covalent-radius ratio), then a set of hardcoded normalisation rules, then a valence-ceiling relaxation. The relaxation had two structural faults. It was **one-directional** — a neighbour's order could only be walked *down* (`3 → 2 → 1.5 → 1`) and never raised again, so the deficit it tried to remove was paid by whichever neighbour happened to be listed last, and an over-coordinated atom could never recover the orders the geometry actually supported. And it had **no entry for any pair absent from the element-pair table**: a `O–H` bond is listed under `O+H`, so the "which neighbour may I downgrade" scan skipped it silently (`if (!specs) return`) and the surplus was charged to a **different** bond instead — which is exactly the reported defect. A hydroxyl oxygen that also accepts a hydrogen bond (an `O···H` contact inside the `H+O` cutoff) therefore carries three neighbours where its ceiling is two, and the code took the extra unit out of `O–C`, converting a C–O single bond into a double or a triple; the hydrogen it should have been fixed against was never a candidate, so the `O–H` itself also climbed to order 2 or 3. On the bundled corpus the old code got **54 of 83** O–H bonds wrong (`{1: 29, 2: 46, 3: 8}`). The two hardcoded rules that were supposed to catch this had the same blind spot: `fixBondOrders` listed only `C+O`, `Br` and `N`, so an `O` centre fell through untouched, and its `N`-only second pass would have pinned a nitro group's `N–O` to a single bond.
  The normalisation is now read straight out of the element-pair table (`allowedOrders`) instead of being spelled out pair by pair, so no element pair can be left out of it, and the relaxation is replaced by `relaxCenterValence`, which re-plans each over-coordinated centre **from scratch and reversibly**: candidate orders for a bond are limited to the values the **measured distance actually supports** (inside that spec's tolerance, or the pair's closest fit — so a long non-bonded contact can never be promoted into a multiple bond), the plan must keep the centre within its ceiling, must not push any neighbour over its own ceiling (per-neighbour `headroom`), and is accepted only when it **strictly lowers the total deviation** of the centre's neighbours from their table ideals. Both directions of movement are available, and a balanced **pair** move (two neighbours by the same amount) is searched as well as single transfers, which is what an exchange between two equivalent bonds needs. Because a plan is only accepted when it is strictly better than leaving the atom alone, the pass is **idempotent** — re-running it changes nothing, so the fixed-point loop always terminates. Terminal elements (`H`, halogens, noble gases) are pinned to a single bond and excluded from a centre's re-assignment budget, which preserves the old `N`-with-hydrogen rule without hardcoding it. Inputs above 20 000 atoms skip the pass, so a concatenated trajectory cannot pay for a sweep whose result is not wanted.
  Verified on the full bundled corpus (27 structures, 8196 bonds) against a character-faithful reference of the **pre-fix** algorithm: O–H goes from **54 wrong to 0** (`{1: 83}`), and the fix is a strict improvement on every pair that changed — `H+N` `{1:270}`, `O+P` and `O+S` (no table entry at all, so they snap to single instead of inventing `P=O`/`S=O`), `N+Te` at 1.97–2.01 Å (physically only a single bond), `N+O` now correctly a **double** bond for the 1.20–1.24 Å nitro groups (`{2:112, 1.5:20}`; the old code forced all 132 of them to single because `MAX_VALENCE.N = 3` has no charge dimension), and thiophene-type `C–S` at 1.78 Å keeps its aromatic order instead of being downgraded a whole unit to pay a valence debt. The host detector and the webview's inline copy agree **bond-for-bond on every file** (0 mismatches), and both re-runs are identical (27/27). Targeted probes confirm the reported case directly: a hydroxyl with a 1.6 Å hydrogen-bond acceptor comes out `O–H 1, O–C 1, C–H 1`; water is two single bonds; nitromethane is `N=O ×2`; benzene is six 1.5 bonds; ethyne is a triple bond.

- **SMILES → 3D: ring substituents and fused aromatic rings were not planar** — Benzene came out with its six hydrogens alternately above and below the ring plane (up to **0.239 Å** out of plane, H–C–C–C off by **14.5°**), and the deflection grew with substituent mass: toluene 0.641 Å / 27.7°, phenol 0.444 / 20.6, aniline 0.688 / 31.1, pyridine 0.291 / 17.9, furan 0.639 / 42.4, pyrrole 0.614 / 40.4, benzoic acid 0.662 / 28.6, styrene 0.769 / 33.3, benzonitrile 0.482 / 20.6, aspirin 0.842 / 39.1, caffeine 0.847 / 47.1 — so a flat aromatic ring looked rippled. Root cause: the direction of a ring substituent is fixed only by a **dihedral**, and a coplanar dihedral is an *extremum* of every distance, so the distance-projection solver is blind to it — the ~0.002 Å residual left by the bond-length/angle constraints is amplified into an out-of-plane deflection (the same amplification the engine already documents for ethylene). The ring-plane projection moves ring atoms only and never reaches the substituents, while projecting ring atoms onto their neighbours' plane instead would fight the ring-plane projection and warp the ring. Both are fixed by two **strain-free rigid-rotation** passes that run last, after relaxation and the chirality fix, so nothing can undo them: (1) *fused rings* — each ring sharing a bond with an already-flat ring is rotated about that common bond so that the two of its atoms attached to that bond lose their out-of-plane component; the rotation angle has a closed-form least-squares solution, and of the two solutions that coplanarise the ring the one that keeps the ring on its own side of the shared bond is taken (the other flips a fused ring bodily onto its neighbour, which is invisible to bond lengths and shows up only as overlapping atoms); for a ring that is itself planar this lands it exactly in the reference plane, and the same pass also covers an aromatic ring fused to a **saturated** ring (indane, tetralin), whose two benzylic bonds must also lie in the aromatic plane — there the least-squares angle splits the deviation between the two bonds, which is the best a rigid rotation can do, the residual coming from the saturated ring's own internal angles rather than from a free direction; (2) *substituents* — every sp2 ring carbon with two ring neighbours plus one exocyclic neighbour is rotated, whole branch included, onto the outward bisector of its two ring bonds (the third sp2 σ direction, which for a six-membered ring makes 120° with each ring bond). Rigid rotation changes no bond length and no bond angle, so the relaxed local geometry is preserved exactly — **max bond deviation is unchanged everywhere** (benzene 0.0033 Å, naphthalene 0.0077, aspirin 0.0393, caffeine 0.0237; identical before and after). Result across 22 aromatic cases (benzene, toluene, xylene, phenol, aniline, pyridine, furan, pyrrole, benzoic acid, benzonitrile, styrene, biphenyl, naphthalene, 1-methylnaphthalene, anthracene, phenanthrene, quinoline, indole, benzofuran, caffeine, purine, aspirin): substituent out-of-plane deviation ≤ **0.010 Å** and dihedral deviation ≤ **0.03°**, fused-ring angles ≤ **0.43°**, rings still flat (≤ 0.005 Å), zero close-contact flags, and naphthalene's crowded peri H···H back to **2.411 Å** (experimental ≈ 2.44 Å). Non-planar rings are untouched (cyclohexane, glucose's pyranose ring, alanine, bicyclo[2.2.2]octane, cyclohexane-1,4-dione), and every torsion/chirality control is bit-identical (`C/C=C\C` 180.00°, `F/C=C/F` −179.99°, `FC(/C)=C/F` 147.87°, `@@` → +1, `@` → −1). An aromatic ring fused to a saturated ring improves from **0.99 Å to 0.28 Å** (indane) and **0.86 Å to 0.20 Å** (1-methyltetralin), the residual being a symmetric ±0.28 Å twist instead of a one-sided 0.99 Å lean — tetralin only reaches 0.57 Å, because its saturated ring's internal angles are further from what planar benzylic bonds need, and a rigid rotation cannot change an angle (a force field resolves that by letting the ring's angles relax). Two traps were caught by the close-contact metric rather than by bond lengths — both left every bond length correct while placing atoms **0.008 Å** apart: a fused ring's third neighbour must **not** be treated as a free sp2 substituent (its direction is dictated by the other ring, not free), and zeroing the out-of-plane component has a second solution **180° away** which flips a fused ring bodily onto its neighbour. Cost: below the measurement noise floor — the 9-case timing suite reads 35.80 → 36.90 ms between the two back-to-back builds, but re-measuring the *same* build minutes apart already moves by ~1 ms, and the ring-free 56-atom control (which neither pass can touch) moves by as much as the ring-bearing molecules; structurally the added work is one pass over the ring atoms per molecule, against a relaxation loop of up to 500 iterations over every constraint. This deliberately goes beyond the reference implementation, which produces the same non-planar geometry — the planarity passes are the one place where the generated coordinates are expected to differ from it
- **SMILES → 3D port: the cis/trans reference substituent was not direction-aware** — The ported torsion-target builder picked each double-bond endpoint's reference substituent as `subs[0]` instead of the substituent carrying the `/` or `\` direction mark, so whenever the mark sat on a substituent that was not the first in adjacency order (e.g. `FC(/C)=C/F`) the same-side/opposite-side verdict for that pair was inverted and the enforced dihedral came out cis where the Python original produces trans. Found by differential testing against the Python engine and confirmed by mutation: restoring the pre-fix selection makes exactly those two inputs (`FC(/C)=C/F`, `FC(/C)=C\F`) diverge from the reference by **1.82 Å** while every other case stays identical — so the passing run proves the fix rather than merely being consistent with it. Two further fidelity details were aligned with Python semantics while completing the port: the torsion scan's angle wrap now uses sign-of-divisor modulo (`modPositive`) instead of JS `%` (which keeps the dividend's sign), and the unclosed-ring error text reproduces Python's list formatting (`环编号 [1]` rather than `环编号 1`). The file was also incomplete before — `buildInfo` had been left without a body, which meant `dist/parsers/smilesTo3d.js` was never emitted; the module now compiles clean and is part of the build
- **Convergence energy axis collapsed to `0 0 0 1 1` on runs that cross an integer** — The Energy chart prints one shared integer base in the title and only the changing fraction on the ticks (e.g. `.67 .66 .65` for a run around -47077). The number of decimals was decided by "the first decimal place at which the run's two ends differ", which returned **0** whenever the ends' integer parts differed — even when the run's total span was smaller than one unit. A run from `-6911.977` to `-6912.806` (span 0.83, crossing the −6912 boundary, exactly the shape of a real `test/1873512_2met.log` optimization) therefore rounded every gridline to a whole number and the axis read `0, 0, 0, 1, 1`. The decimal count is now derived from the gridline **step** (span / 4) — two significant digits of the step — so five distinct labels are always produced. The base is also now picked on **one side** of the range (`ceil(vmax)` for a non-positive run, `floor(vmin)` for a non-negative one, none when the range straddles an integer or zero, or spans ≥ 1), which keeps the printed fractions monotonic top-to-bottom; runs that do **not** cross an integer keep their previous integer part and `.xx` style byte-for-byte. A tick landing exactly on the base prints `0` instead of the previously stripped `000`, and the left gutter is now sized to the labels (falling back to the old 40 px when they are short) so a fine span with many decimals no longer overflows
- **Convergence hover tooltip rounded large-magnitude energies to a whole number** — The point tooltip formatted every value with a magnitude-based rule that gives **0** decimals for numbers in the thousands, so hovering a step on the Force / Displacement charts reported `Energy = -6912` — useless when the whole point of the tooltip is to separate steps that differ in the third decimal. The tooltip now keeps the decimals needed to resolve the series' own span (the same step-based rule as the axis) and never drops below 3 decimals, capped at 10, so the energy reads `Energy = -6912.806` and a force reads `0.000451`; the Energy chart's own tooltip gains the same resolution
- **Right-drag panning in diff mode moved the wrong structure (right side appeared un-draggable)** — In Structure Diff mode the canvas is split into two independent viewports (left = original, right = comparison), each with its own pan offset (`panX/panY` vs `diffPanX/diffPanY`). Three defects combined to make the right structure impossible to pan: (1) `initPanGrab` returned early whenever `diffMode` was set, so the cursor-locked grab was never established in diff mode; (2) even on the delta fallback path, the mousemove handler always wrote to the **left** viewport's `panX/panY` regardless of which half was grabbed, so a right-drag on the comparison structure silently panned the original one instead; (3) the pan ray math mapped the cursor through whole-canvas NDC and used the base camera distance/aspect, which is wrong for a half-width viewport. Panning is now viewport-scoped and cursor-locked on both sides: the grab records the grabbed side (`panGrabSide`) plus a per-side reference plane and grab offset, the ray is cast with the camera configured exactly like the render pass for that side (`configureDiffCamera` uses the half-width aspect and that side's camera distance), and mousemove applies the drag to that side's own pan offset. The right structure now follows the cursor 1:1 under middle/right-drag, the left structure is no longer dragged while panning the right one, and the delta fallback (used only when the reference-plane ray is degenerate) is also side-scoped. View rotation, wheel zoom, box-select and non-diff panning are untouched — in particular the non-diff pan path still uses the original whole-canvas projection, so single-view behaviour is byte-identical
- **Gaussian log route section basis-set parentheses misparsed as keyword options** — Route keywords containing basis set names with parentheses (e.g. `RwB97XD/6-31G(d,p)`, `M06-2X/6-311++G(2df,2p)`, bare `6-31G(d,p)`) were incorrectly split into a keyword and an option list (e.g. `RwB97XD/6-31G` + `d,p`), which the Route panel then rendered as `RwB97XD/6-31G = d, p`. - **Gaussian log route section line-wrapping keyword reconnection** — When a Gaussian route card spans multiple lines (column-80 wrapping), a keyword could be split across lines (e.g. `force` → `for` / `ce`) and the original `.join(' ')` concatenation inserted a space between the fragments, causing the tokenizer to produce two separate keywords instead of one. The route-line collection now uses a smart `joinRouteLines` function that decides per adjacent line-pair whether to merge without a space: (a) when the merged fragments form a known Gaussian keyword (from a ~120-entry keyword set covering methods, basis sets, options, and common flags), (b) when parentheses are unbalanced across the break (indicating a split option list), or (c) when the previous line ends with `=` or `(` (incomplete token); a guard prevents merging when the previous line is itself a standalone keyword preceded by a space. The route-collection loop also no longer breaks on `#`-prefixed continuation lines — a `#` line after a non-blank/non-dash line is now treated as a continuation rather than a new section start

### Fixed

- **A CIF's symmetry was read from one of three dictionary generations, and the other two loaded as P1 without a word** — The reader looked for `_symmetry_equiv_pos_as_xyz` and for nothing else. The core dictionary (CIF 1.2) writes the same list as `_space_group_symop_operation_xyz`, CIF 2 writes `_space_group_symop.operation_xyz` (the data name is split by a dot, not an underscore), and the space-group name has the same three spellings — so a file written under any of the newer ones reached the expander with **one operation, the identity, and no warning at all**, and was drawn as P1: a two-site structure that states two operations came out as two atoms instead of four, with nothing on screen saying the cell was half empty. Lookups now go through a **normalised tag** (`_space_group_symop.operation_xyz` and `_space_group_symop_operation_xyz` are one name, and the same rule makes a CIF 2 file's `_atom_site.fract_x` the same column as `_atom_site_fract_x`) and a priority list per concept, and they are exact instead of substring matches — `_geom_bond_atom_site_label_1` can no longer answer a question about `_atom_site_label`, nor `_atom_site_aniso_label` one about `label`. Operations are read from a loop, from a one-row item, or from a semicolon text block, and a file that lists the same operation twice now expands it once. **What cannot be read is said**: a file with no operation tag ends in the structure panel as `no symmetry operations in the file: read as P1 (declared space group P -1)`, and a tag whose contents make no sense as `no readable symmetry operation under _space_group_symop.operation_xyz: read as P1`. A bare `_key` followed by a `;` block — how a multi-line space group or systematic name is spelled — used to be tokenised and then dropped, leaving the item empty; the block is now attached to the name above it. Verified by writing the same structure under all three generations and comparing the cells atom for atom to nine decimals (identical), by the CCDC 142619 fixture (294 atoms, C138 H116 N14 O26, unchanged), and by 140 assertions with 20 mutations, every one of which the suite catches.

- **A CIF number, an element symbol and a `?` were taken at face value** — `parseNumber` called `parseFloat` on whatever it was handed, so a file without `_cell_length_a` threw `Cannot read properties of undefined` out of the parser instead of loading; `?` was a value like any other, which is how a file whose `_symmetry_space_group_name_H-M` is `?` came to show `SG: ?` in the panel, write `'?'` back into a saved CIF and use a question mark as its title; and an oxidation state stayed in the element name, so `Fe3+` became an element called "Fe3+" and missed every table the viewer has — radius, colour, valence, mass. Now a non-string is a missing field; the number ends at the first `(` of `10.7307(7)`, which also survives an uncertainty that lost its closing bracket where deleting brackets would have glued the digits on; `?` and `.` are absent everywhere, so a missing space group is not a group and is not written back; the element is the leading run of letters with the state removed (`Fe3+` → `Fe`, `O2-` → `O`, `Cu(II)` → `Cu`, `N+` → `N`); and an incomplete unit cell returns an **empty structure with a warning** instead of a 1 Å cube, which is what `parseCif('data_x\n')` used to throw on. A missing cell angle still defaults to 90°, but now says so. Verified: `parseCif('data_x\n')` returns no atoms and one warning; five oxidation-state spellings come out as their elements; `?` reaches neither the panel nor a save.

- **Two CIF sites 0.3 Å apart were folded into one atom** — Symmetry images were deduplicated at a 0.5 Å radius (`dx² + dy² + dz² < 0.25`), a full bond length's worth of slack. That is far more than rounding needs: the only images that must coincide are a site's own images on a special position, and they land on each other to within 1e-9 Å — so the tolerance was really deciding which *distinct* sites the file lists would survive, and a split or partially occupied pair 0.3 Å apart came out as a single atom. The radius is **0.1 Å** now, and a merge above 1e-4 Å — anything that is not an exact image — is **reported**: `site C2: an image 0.050 A from an existing atom was merged into it`, capped at six plus a count. Folding an exact image onto a special position stays silent: that is what symmetry does, and a warning per special position would drown the cases worth reading. The dedupe itself moved from an all-pairs scan to a **grid** one tolerance wide, because expansion compares every image against every atom placed so far and that is quadratic in a framework's atom count: 2000 sites × 24 operations (7 987 atoms) now parse in **19 ms** end to end, against **184 ms** for the all-pairs dedupe alone on the same images. Verified: sites 0.30 Å apart stay two atoms, 0.099 Å merges and 0.101 Å does not, and 142619 is unchanged at 294 atoms with the same element counts.

### Added

- **The asymmetric unit a CIF lists is kept, not only the cell it expands to** — `CrystalData` gains `asymAtoms`: one entry per `atom_site` row, carrying the site's element, label, cartesian and fractional position, occupancy, and **the indices of the symmetry operations that actually placed an image of it** — a site on a special position lists only what survived, a site that duplicated an earlier one lists none. `baseAtoms` remains the expanded cell the viewer draws, atom for atom what it was before, so the two now answer different questions: what is on screen, and what the file says. Nothing but the parser writes the field; a CIF save-back can now be written from the asymmetric unit rather than from the expanded cell under the full operation list (which re-expands on the next read), and that is the next batch's job. Verified on 142619: 147 sites for 294 atoms, every base atom accounted for by exactly one site/operation pair, every site's own position present in the cell, the occupancies carried both ways, and a re-parse giving an identical asymmetric unit.

- **Parser warnings reach the structure panel** — `MolecularData` gains `warnings`, the short list of decisions a parser had to make, and the page shows the first of them — plus a count of the rest — as one amber line at the end of the structure panel. This is the channel the CIF work needed, because a structure that is not what the file literally says must not look like one that is; it is deliberately not a log, so a file that parsed cleanly adds nothing and the panel reads exactly as before, character for character. A warning is HTML-escaped before it is shown, since a site label or a space-group name is the file's own text, and the space-group line was escaped at the same time.

## [0.5.0] - 2026-04-15

### Added

- **MOL2 file support** — New parser for Tripos MOL2 format (`.mol2`), reads `@<TRIPOS>ATOM` and `@<TRIPOS>BOND` sections with bond order support (including aromatic `ar` → 1.5)
- **Gaussian LOG file support** — New parser for Gaussian output files (`.log`, `.out`), reads `Standard orientation:` and `Input orientation:` coordinate blocks
- **Optimization trajectory navigation** — When opening a LOG file with multiple structures, ◀ Prev / Next ▶ buttons appear in the toolbar to step through optimization frames; frame counter shows current step and label
- **Jump to frame** — Direct input field to jump to a specific frame number in optimization trajectory
- **Auto play** — Automatically cycle through all optimization frames with 500ms interval
- **Fixed atom notation in GJF** — Enhanced GJF parser to handle coordinates with fixed atom markers like `C  -1  -7.678  -1.467  1.374` or `C  -7.678  -1.467  1.374  -1` by extracting the last 3 numeric values as coordinates
- **Aromatic bond display** — Aromatic bonds (order 1.5) now render as one solid line + one dashed line, distinguishing them from double bonds

### Changed

- **GJF connect section parsing** — No longer searches for explicit `connect` label; instead directly checks content after the blank line following coordinates. Lines are validated as all-numeric with max atom number ≤ total atoms; single-number lines (atoms with no additional bonds) are allowed
- **Bond order estimation thresholds relaxed** — Tightened double/triple bond thresholds to reduce false positives: triple ≤ 0.78 (was 0.80), double ≤ 0.88 (was 0.90), single > 0.88

### Fixed

- **Bond order display bug** — Bond orders > 1 from file connect sections were not displayed correctly in 3D (all showed as single bonds). Root cause: GJF parser used `Math.round()` which could alter bond orders, and `createBond` used strict `===` comparison that failed for float values. Fixed by preserving original float bond orders and using range-based comparison (`ord < 1.25` for single, `ord < 1.75` for aromatic, `ord < 2.5` for double, `ord < 3.5` for triple)
- **GJF connect section not detected** — Lines with only an atom number (no bond pairs, e.g. `43`) were incorrectly rejected by the `tp.length < 2` check, causing the entire connect section to be skipped. Fixed by allowing single-number lines in validation

## [0.4.0] - 2026-04-15

### Added

- **Extended element selection** — Add Atom dialog now includes 70+ elements (periods 1-6, common transition metals and lanthanides) instead of just 10
- **Bond order selection when adding atom** — Choose single, aromatic (1.5), double, or triple bond when adding a new atom
- **Bond order editing** — Bond Length modal now shows current bond order and allows changing it (single ↔ aromatic ↔ double ↔ triple); changes are reflected immediately in 3D display
- **GJF connect section in saved files** — When saving as GJF format, bond connectivity information (atom indices + bond orders) is now correctly written in the connect section, keeping atom numbering and bond data consistent after add/delete/edit operations
- **Default save path** — Save As dialog now defaults to the directory of the currently opened file instead of an arbitrary location

### Fixed

- **Variable declaration order** — Moved `selectedAtoms` and other state variables before `rebuildScene()` call to fix `indexOf` undefined error that caused black screen

## \[0.3.0] - 2026-04-14

### Fixed

- **Black screen root cause (final fix): Three.js now inlined into HTML** — Instead of loading Three.js as an external file (which failed due to CDN unreachability and local file loading issues in webviews), the library is now read at runtime and embedded directly into the HTML. This eliminates ALL script loading failures regardless of network, CSP, or webview configuration
- **CSP simplified** — `script-src` no longer needs external domains or `webview.cspSource`; only `'nonce-xxx'` is required since Three.js is inline
- **Visible loading indicator** — Shows "Loading 3D Viewer..." text while initializing, so users know the webview is working
- **Comprehensive error handling** — Added `try/catch` around entire initialization; any JavaScript error now displays a visible red error message instead of a silent black screen
- **Loading state management** — Loading indicator is hidden once Three.js renderer is created; error messages properly hide the loading indicator

## \[0.2.2] - 2026-04-14

### Fixed

- **Black screen root cause: Three.js CDN unreachable** — Bundled Three.js r128 locally in `media/three.min.js` instead of loading from cdnjs.cloudflare.com, which is often blocked or slow in China and corporate networks
- **Local resource loading** — Changed script loading to use `webview.asWebviewUri()` for reliable local file access, compatible with both local and Remote-SSH scenarios
- **CSP updated** — Replaced `https://cdnjs.cloudflare.com` in Content Security Policy with `webview.cspSource` for proper local resource authorization

## \[0.2.1] - 2026-04-14

### Fixed

- **Black screen on startup** — Changed layout from absolute positioning to CSS flexbox for the toolbar, status bar, and 3D container, ensuring the container always has correct dimensions
- **Container dimension fallback** — Added fallback to `window.innerWidth/innerHeight` when `container.clientWidth/clientHeight` is 0, preventing Three.js renderer from creating a 0×0 canvas
- **Three.js load check** — Added check for `THREE` undefined with visible error message when CDN fails to load
- **`acquireVsCodeApi()`** **multiple call bug** — Moved API acquisition to top-level (once per session) instead of inside `doSave()`, preventing error on second Save As click
- **CSP inline style violation** — Replaced inline `style="background:#c33"` on Delete button with CSS class `.mbtn-danger`, complying with Content Security Policy
- **Error display element** — Added `#error-msg` element for showing runtime errors to users instead of silent black screen

## \[0.2.0] - 2026-04-14

### Added

- **Molecular Editing Toolbar** — Mode-based toolbar with View, Bond Length, Bond Angle, Dihedral, Add Atom, Delete Atom, Save As, and Reset View buttons
- **Bond Length Adjustment** — Click 2 atoms to select, modal shows current bond length, choose which atom to fix/move, adjust via numeric input or slider with real-time 3D preview
- **Bond Angle Adjustment** — Click 3 atoms (2nd is central), modal shows current angle, fix/move either side, real-time 3D preview
- **Dihedral Angle Adjustment** — Click 4 atoms, modal shows current dihedral, fix/move either side, real-time 3D preview
- **Add Atom** — Click anchor atom, choose element (H/C/N/O/F/P/S/Cl/Br/I), set bond length, auto-calculated direction based on existing bonds
- **Delete Atom** — Click atom, confirm deletion; automatically re-indexes atoms and bonds
- **Save As** — Export modified structure as XYZ or Gaussian GJF format via VS Code save dialog (original file is never modified)
- **Atom Selection Highlighting** — Selected atoms glow yellow (emissive) for clear visual feedback
- **Status Bar** — Shows current editing mode and selected atoms
- **Cancel/Undo** — Cancel button in edit modals restores original coordinates
- **BFS Fragment Detection** — `getMovable()` uses breadth-first search to correctly identify which atoms move when adjusting geometry
- **Rodrigues Rotation** — `rotAroundAxis()` implements Rodrigues' rotation formula for accurate rotation around arbitrary axes
- **Real-time 3D Preview** — Slider and input changes immediately update the 3D molecular view
